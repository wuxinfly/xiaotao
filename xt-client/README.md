# XiaoTao 客户端

Agent 的回答提示要求先回应问题、按需展开，并保留必要依据、风险和未完成事项；用户指定格式和细节时优先遵守。此调整无需额外模型请求，实际文风仍取决于模型，真实模型对比验收尚未完成。Mermaid 图示渲染尚未实现。

Agent 会话标题区域提供“复盘”与“复盘记录”功能：在任务执行结束后可手动复盘小涛的执行行为（理解要求、工具调用、异常处理、验证响应等），分析结果持久化保存在当前环境 SQLite 的 `behavior_reviews` 表中，重启自动恢复遗留任务；支持查看结构化详情和单份独立 Markdown 下载导出；支持将确凿的问题快照加入已启用 `.xiaotao/` 的项目建议箱；执行与复盘严格互斥，全局并发上限为 2。设计与验收见 [小涛 Agent 手动行为复盘方案](../docs/plans/2026-11-07-agent-behavior-review.md)。

Agent 长 query 会在消息气泡内换行，代码块保留格式并在块内横向滚动，不撑宽会话。工具调用与结果成对保存，续聊时完整恢复；旧版缺少调用的工具结果作为标注的历史参考文字保留，执行中断缺少结果时明确标注未知，不伪造成功。引用对话仅摘取用户消息与正式回复，不包含工具调用过程。修复与验收见 [消息宽度与工具历史](../docs/plans/2026-11-07-agent-tool-history-layout.md)。

## Qoder 接入（2026-11-01）

账号与配额 → 添加账号 → 选择 Qoder 国内版或海外版后，在浏览器完成设备授权。授权窗口为 10 分钟，可取消、复制链接或重新打开；账号详情支持按原区域重新登录。同 UID 在两区分别保存，凭据仍由 Windows DPAPI 加密。设备 token 刷新由聊天、模型目录和额度共用按账号加锁的入口，轮换结果不会覆盖重新登录或已删除账号。

模型从该账号上游目录获取，在当前环境持久缓存，不按时间自动过期；“刷新列表”刷新当前来源下的账号目录。失败时显示上次目录与错误，无历史目录则显示不可用，不用静态模型冒充账号权益。外部工具使用完整的 `qoder/<模型名>`（如目录中的 `qoder/qwen3.8-flash`），未知新模型的公开 ID 带稳定 key 摘要以避免重名。

已实现 OpenAI Chat Completions 的流式/非流式、reasoning、工具参数分片、图片内容透传、真实 token usage；上游 HTTP 或带内错误会失败，未收到完成标记的断流不会伪装成功。连接上限 15 秒、聊天空闲上限 300 秒、总时长 30 分钟。`10605` 是上游按账号和模型周期排队，不是额度耗尽：兼容带内外层 `403`、message 内嵌 `10605` 的排队响应（普通 `403` 不重试）；首个有效事件前按 `retryAfterSeconds` 在同一账号最多等待重发 2 轮，单次等待上限 60 秒，不冷却或换号；已开始输出后不重放，其他错误仍直接失败。订阅、加购、活动资源包分别显示，标题合计已知积分；独立到期日期显示为“到期”，缺失数值保留未知。

验证边界：当前通过本地 mock、Go 回归、前端和 Windows EXE 构建；CN / Global 真实账号授权、模型权益、聊天与额度尚未实测，桌面壳交互仍待验收。自动签到、PAT/本机凭据导入、Responses/Anthropic 入口不在本期范围。详细记录见 [Qoder 实施计划](../docs/plans/2026-11-01-qoder-proxy.md)。

已实现 Windows 客户端：Go 独立本地服务、嵌入式 Web 页面、系统 WebView2 窗口及浏览器入口。模型代理已接入 Trae 国内版、WorkBuddy（国内版）与 Antigravity（Google OAuth）账号反代。小涛 Agent 已具备多会话独立执行能力：选择模型后即可对话；可选择项目，未选项目时使用数据目录内的默认工作目录。Agent 可以查看文件、修改代码、运行验证并停止任务。

首次使用 Agent 时，在“Agent 设置”中选择常用模型并保存，再从输入区选择模型。模型目录从启用的账号并行获取；加载失败或超时可重试，列表为空时可前往“账号与配额”检查账号。已保存的模型会保留，但实际调用仍取决于账号状态和上游可用性。

Agent 设置、账号页与 `/v1/models` 共用服务端模型目录，按账号和区域保存在当前环境的 `accounts/accounts.json`，重启后继续使用。首次没有目录时自动拉取一次，成功返回的空目录也缓存；成功目录不按时间自动请求上游。首次获取失败时的内置兜底会在后续读取时每分钟最多重试一次，重启后可立即重试。Agent 设置“刷新模型列表”并行刷新所有来源的启用账号；账号页“刷新列表”只刷新当前来源下的账号。刷新失败保留原目录并提示，可重试；正常 token 续期保留目录，重新登录后重新获取，删除账号清理缓存。浏览器不再独立保存模型目录，已选模型和标签仍保留。

Agent 设置中的模型按来源默认折叠，点击来源可展开；搜索时自动展开匹配的来源，清除搜索后恢复折叠。

Agent 设置使用左右布局：左侧为常用模型、默认模型、MCP 工具和 Skills 技能，右侧显示当前配置。常用模型页只展示已经配置的执行模型，通过“添加模型”从账号目录选择；每个已配置模型可填写上下文窗口和最大输出。上下文窗口默认采用账号目录输入窗口，最大输出留空表示由上游默认值决定。目录声明支持 reasoning 的模型会额外显示思考等级下拉框，可选档位来自模型目录（如 Trae 的 light/medium/high/extra_high/max）；留空表示跟随上游默认档。保存前校验最小值和“最大输出必须小于上下文窗口”。参数与模型 ID 一起保存在当前环境的浏览器存储。新会话保存实际参数快照，后续设置变化不直接改写已有会话；切换模型时沿用新模型对应的配置。发送消息时参数随请求进入本地代理，`max_tokens` 会按各来源协议透传；`reasoning_effort` 在代理层统一归一化（none/minimal/light→low，ultra/extra_high→xhigh），并按模型目录声明的档位就近取，模型未声明对应档位时不下发该字段。

默认模型是独立配置页，分别为 AI 重命名、行为复盘和上下文压缩选择辅助模型；不选择时继续跟随会话模型。标题生成和复盘调用已携带所选默认模型及其参数，压缩项先保存配置，供上下文压缩实现读取。上下文窗口也用于输入区的用量百分比和后续压缩阈值，当前运行统计仍以实际返回的输入用量或本地 UTF-8 估算为准。前端回归：在 `frontend` 运行 `node --test tests/agent-model-settings.browser.test.mjs`。

输入区下方显示当前任务的工作目录；未选择项目时会说明使用小涛数据目录内的默认工作区。较长路径可将鼠标悬停在说明上查看完整内容。

新会话可在输入区的项目选择器中搜索并切换已有会话的项目，也可选择新的项目文件夹或使用默认工作目录。已有会话的项目不可更改；选择历史项目时会检查目录是否仍然存在。

会话列表按最近更新时间排序，采用紧凑单行，不显示更新时间。左侧留白显示状态：运行中为青绿色呼吸点，离开会话后完成为静态青色未读点，失败为琥珀色未读点；打开对应会话后清除。未读状态保存在当前环境的本地浏览器存储，重启保留，首次使用不会把旧历史标成未读。停止任务不标未读；减少动态效果时运行点保持静态。

按项目查看时，项目标题无常驻底色，仅悬停时显示背景反馈；键盘操作保留焦点框并显示项目操作按钮，鼠标点击后移出不会保留高亮。会话仅文字向右缩进，悬停和选中背景铺满整行；会话行高 38px，项目组之间保留 16px 留白，便于区分归属。“最新”分组沿用相同层级。按会话查看时保持平铺。

会话行悬停或键盘聚焦时显示三个点，点击或右键会话可打开“重命名、删除”菜单。重命名会保存到本地，删除仍需确认；运行中的会话须先停止再操作。重命名弹窗提供“AI生成”，按当前会话最近的消息、进展和正式回复生成短标题，先填回输入框，仍需手动保存；空会话、模型失败或超时会保留输入框内容并显示原因。生成请求随弹窗关闭取消，不写会话历史或用量统计。

删除会话成功后，该行用 180ms 轻微左移并淡出，后续行用 220ms 平滑补位；离场行不可交互。删除失败保留原行，系统开启“减少动态效果”时直接移除。
删除属于项目的会话时会同时保存该项目分类，即使原先只是选择了目录，删光会话后项目仍留在侧边栏；已主动删除项目后归入“最新”的会话不会重新创建项目。项目文件夹不受影响。

项目级弹窗外壳位于 `frontend/src/components/modal/ModalFrame.tsx`，样式随组件加载，提供标题、说明、内容和底部插槽，并统一处理 Portal、焦点循环、Escape 关闭及焦点恢复。Agent 设置、项目选择和会话重命名均使用该组件，底部操作按钮靠右排列。

公共弹窗优先以触发控件为缩放和位移动效的起点，也可通过 `origin` 指定视口坐标；无触发位置时从上方向下淡入。减少动态效果设置下关闭位移和缩放动画。

使用 `ModalPresence` 包裹条件渲染的弹窗，可在关闭时保留 180ms，向上偏移淡出后移除；离场期间禁止交互。

小涛每次接收消息时会读取所选工作目录根部的 `AGENTS.override.md` 或 `AGENTS.md`，优先读取非空的前者，并将内容作为项目指令发送给模型；文件须为 UTF-8，最大 32 KiB，读取失败会报错。子目录规则目前由模型按提示主动查找，不能保证自动加载；不读取项目外的全局指令，也不支持自定义备用文件名。

产品范围、分发更新规则和待定事项见[客户端总体方案](../docs/architecture/xt-client-overview.md)。

## Trae、WorkBuddy 与 Qoder 签到（2026-11-06 更新）

WorkBuddy 代理会合并完全相同的同名工具；同名工具定义不同时返回冲突错误，请客户端合并后重试。为兼容上游渠道校验，WorkBuddy 请求中的 developer 角色会转为 system；首条 system 提示词若以已知 DeepSeek Harness 或 Claude Code 身份句开头，会将该句替换为中性占位文本，其余内容保留。上游仍返回 11128 时会说明原因，并在本机运行日志记录前 20 条消息的角色、内容类型及是否包含已知身份句，不记录消息正文或凭据；实际可用性取决于上游策略。

针对具备每日签到积分的上游平台（Trae 国内版、WorkBuddy、Qoder 国内/海外版），客户端支持手动打卡与签到状态查看：
- **Trae**：针对国内区（CN）账号接入 `/trae/api/v2/ug/checkin_credits/{status,claim}`，内置稳定设备指纹派生与风控换机重试（海外账号自动跳过不请求）。
- **WorkBuddy**：接入活动状态查询 `/v2/billing/meter/checkin-activity-status` 与打卡领积分 `/v2/billing/meter/daily-checkin`。
- **操作交互**：账号卡片及详情弹窗显示打卡状态徽标，支持单个账号点击签到打卡，并在来源分组头部提供“一键打卡”批量签到。打卡成功后等待约 5 秒再自动刷新账号配额，避免上游积分尚未同步时读到旧配额。

## 构建与验证

当前验证环境为 Windows amd64、Go 1.27、Node.js 22。开发构建需要 Node.js，最终用户无需 Node.js 或 Python。前端采用 React + TypeScript + Vite，源码位于 frontend，构建产物嵌入 Go EXE。

```powershell
cd xt-client
cd frontend
npm ci
npm run lint
npm run check:size
npm run build
cd ..
node tools/check-go-size.mjs
go test ./...
go vet ./...
./build.ps1 -Verify
```

客户端代码质量门槛、存量超标文件和 AI 检查流程见
[客户端代码质量规范](../docs/agent/client-code-quality.md)。新增代码不得新增超限文件或函数；
修改已登记的超大文件时不得继续扩大。

`build.ps1` 仅在 `frontend/node_modules` 缺失或不完整时执行 `npm ci`，依赖已就绪时直接构建，避免删除正在运行的 Vite 预览所持有的 `esbuild.exe`。若依赖确实不完整且预览占用该文件，先停止预览服务，再重新运行脚本。

### 不重启服务调试前端

当正式版或 UAT 正在运行、又只想调整页面样式或交互时，不要让 `build.ps1` 或 `--stop` 打断当前实例。另起 Vite 开发服务器，把 `/api` 代理到正在运行的服务：

```powershell
cd xt-client/frontend
npm run dev -- --api-port 5455
```

`--api-port` 填小涛服务的实际端口，正式版通常为 5455，UAT 通常为 5456；端口被占用时以对应数据目录下的 `runtime.json` 为准。打开 Vite 输出的地址（默认 `http://localhost:5173/`）即可。参数只接受 1–65535 的端口号，并优先于 `XIAOTAO_DEV_API`。

也可以沿用环境变量指定服务地址：

```powershell
$runtime = Get-Content -Raw "$env:LOCALAPPDATA\XiaoTao\runtime.json" | ConvertFrom-Json
cd xt-client/frontend
$env:XIAOTAO_DEV_API = $runtime.URL
npm run dev -- --host 127.0.0.1 --port 5460 --strictPort
```

打开 `http://127.0.0.1:5460/` 即可用真实账号、配额和仪表盘数据预览最新前端代码，Vite 修改后热更新。UAT 将 runtime 路径换成 `$env:LOCALAPPDATA\XiaoTao-uat\runtime.json`，并另选预览端口；不要与 5455/5456 冲突。

调试期间注意：

- 只在 Vite 代理内访问运行中的服务，`XIAOTAO_DEV_API` 必须是本机 `127.0.0.1` 地址；代理会把请求的 `Host` 和 `Origin` 改写为服务自身地址，以满足服务的同源校验。
- 预览页面的增删账号、刷新配额、轮换密钥等按钮会真实修改当前实例数据。只调样式时避免点击这些写操作。
- 不把 `XIAOTAO_DEV_API` 或临时代理配置提交到构建产物。默认未设置该变量时，开发服务器不启用代理，正式构建行为不变。
- 验证完成后关闭 Vite 进程并清理环境变量；需要让桌面窗口加载新前端时，再选择合适时机构建和重启，不能中断用户正在使用的服务。

客户端版本记录在 `VERSION`，格式为 `主版本.次版本.构建号`。正式版和 UAT 共用一个版本序列：手动打包（`./build.ps1` 或 `./build.ps1 -Env uat`）时第三位加 1，全部步骤成功后写回文件；失败不递增，并发构建不能同时使用该版本文件。版本同时注入程序及状态接口，旧版本文件不会自动删除。

AI 改代码后自行构建验证必须使用 `./build.ps1 -Verify`，UAT 验证使用 `./build.ps1 -Env uat -Verify`。验证构建沿用当前版本、不写入版本文件，输出到 `dist/verify/`，也不更新桌面快捷方式或带版本号的分发文件。

建议前两位按发布内容手动调整：出现不兼容的重大变化时增加主版本并将次版本和构建号归零；新增兼容功能时增加次版本并将构建号归零。普通修复和日常打包只增加第三位。例如将 `VERSION` 改为 `1.1.0` 后，下一次打包得到 `1.1.1`。

正式构建和 UAT 构建使用同一份源码，但环境身份在编译时注入，互不共用数据目录、端口和单实例。UAT 首次启动时会从正式版只读导入一次已登录的模型账号；代理密钥、用量、配额、配置、Agent 会话、日志和运行时状态仍分别保存：

| 构建 | 输出 | 默认数据目录 | 默认端口 | 桌面快捷方式 |
| --- | --- | --- | --- | --- |
| `./build.ps1` | `dist/xiaotao.exe` | `%LOCALAPPDATA%\XiaoTao` | `5455` | 小涛 |
| `./build.ps1 -Env uat` | `dist/xiaotao-uat.exe` | `%LOCALAPPDATA%\XiaoTao-uat` | `5456` | 小涛 UAT |

固定端口被占用时服务仍会回退到系统分配的空闲端口，实际地址以 `runtime.json` 或 `--status` 为准。`--data-dir` 显式传入时仍以参数为准。

UAT 的模型账号导入只执行一次，导入结果保存在 `%LOCALAPPDATA%\XiaoTao-uat\accounts\accounts.json`，完成标记为同目录的 `import.json`。正式版文件只读取、不写入；之后在 UAT 增删或重新登录账号都不会影响正式版。需要重新导入时，先关闭 UAT，再删除 UAT 的 `accounts` 和 `keys` 目录；不要删除正式版数据。会轮换 refresh token 的来源（如 Codex、Qoder）在正式版和 UAT 同时刷新时可能使另一侧登录态失效，双开测试时优先使用不会轮换的来源，或在一侧测试结束后重新登录。

双击 dist/xiaotao.exe 自动启动隐藏服务进程并打开桌面窗口；未安装 WebView2 时尝试用默认浏览器打开。不安装运行时，不主动写入注册表。当前 EXE 是运行程序，尚不是带版本检查的安装启动器。

build.ps1 构建成功后会在当前用户桌面创建或更新“小涛”快捷方式，指向本仓库 dist/xiaotao.exe；移动 EXE 后需重新构建更新快捷方式。桌面窗口和启动封面使用 Windows 11 系统小圆角；启动封面由原生窗口通过 GDI 帧流渲染 startup.mp4 动画。封面不全局置顶，作为主窗口内的原生子窗口覆盖初始化内容，并随主窗口一起最小化；主窗口在首次显示前去除系统标题栏并挂载动画封面，构造期间使用深色擦除背景；保留正常可见性，让 WebView2 正常加载和绘制。动画约 2.5 秒播完；首屏字体与图片处理完成并满足最短 2.5 秒展示时长后，封面以约 180ms 淡出露出主界面；系统关闭动画效果或窗口已最小化时直接清理。正常启动且前台仍为启动来源时，交接后将小涛带到前台；动画结束后主窗口提升到普通窗口层最前面，不设永久置顶；用户已切换应用时不主动切换键盘焦点。原生窗口和 WebView2 默认背景均为深色；15 秒未收到首屏就绪信号时兜底交接，页面加载失败仍需另行处理。无外部依赖、无安全下载弹窗、无跳过按钮；托盘恢复、页面刷新及浏览器入口不显示启动动画。

## 使用与生命周期

- 默认数据目录：正式版为 LOCALAPPDATA/XiaoTao，UAT 版为 LOCALAPPDATA/XiaoTao-uat；使用 --data-dir 指定其他目录。UAT 仅首次启动时从正式版导入模型账号登录态，其他数据不共享。
- --browser：启动或复用服务，在默认浏览器打开页面。
- --service：只运行服务，主要供启动入口内部调用。
- --status：输出运行服务地址；GUI 构建不便查看标准输出时，可读取数据目录中的 runtime.json，或使用 go run ./cmd/xiaotao --status。
- --stop：停止该数据目录对应的服务。
- 自绘标题栏提供拖动、最小化、最大化和关闭；最大化时原生窗口按当前显示器工作区定位和调整大小，以避开任务栏。多显示器和不同缩放比例的实际桌面效果仍需人工复核。关闭收起到系统托盘，服务继续运行。
- 最小化左侧的“更多”按钮支持点击展开菜单：首项切换浅海 / 深海主题；桌面窗口另有打开安装目录（当前 EXE 所在目录）和当前实例的数据目录（遵循 --data-dir）的操作。支持方向键选择及 Escape 关闭。
- 托盘双击恢复窗口，右键提供打开小涛、在浏览器打开、退出小涛。--stop 同样停止服务及窗口。
- 同一数据目录仅一个服务和一个桌面窗口；正式版和 UAT 版使用不同数据目录与锁，可同时运行；已有窗口时再次打开尝试恢复窗口。
- 启动入口对同一数据目录使用独立启动锁；双击、托盘恢复或并发启动时，健康服务会被复用，不会因启动竞争把正常单实例锁冲突误报为服务启动超时。
- 仅监听 127.0.0.1 回环地址，不向局域网提供服务；正式版优先使用 5455，UAT 版优先使用 5456，端口占用时自动回退到空闲端口。

## 模型用量与仪表盘

在“账号与配额”的各接入来源旁点击“查看模型”，会在弹窗内切换账号查看模型名称与完整调用 ID、复制 ID 或刷新目录。弹窗支持 Escape 和点击遮罩关闭，关闭后焦点回到“查看模型”。列表区分实时、内置、合并与上次目录。Trae 兼容对象/字符串元数据并过滤内部条目，保留上游原始名称。Antigravity 实时发现公开对话模型并合并已验证底表，动态模型携带档位路由；暂不收录生图模型。刷新失败保留上次账号目录，无历史快照时回退内置表。WorkBuddy 从原生 `/v3/config` 获取账号聊天模型目录，无缓存且失败时显示不可用。目录不保证当前账号已获模型权限，实际调用仍取决于来源匹配、权限和额度。页面通过同源 `POST /api/proxy/models?accountId=<id>` 获取指定账号目录，不影响代理路由。
接入来源卡片的标题区域可点击展开或收起，右侧操作按钮独立使用。点击账号打开详情，可设置最多 40 个字符的备注；账号卡片、模型目录和用量展示优先显示备注，清空后恢复显示原账号昵称。备注保存在当前环境的账号数据中。

模型目录：页面刷新与 `/v1/models` 按启用账号聚合，同一来源模型 ID 去重。Trae 优先读取实时目录，过滤关闭、隐藏、自定义和 builder 条目，成功后不再混入静态表；请求最多 10 秒，失败或空目录优先沿用账号上次成功目录，无快照时回退静态表。路由按账号已缓存目录校验模型，实时目录才有的 Max 变体也能正常调用；目录尚未加载时才回退静态表。WorkBuddy 已改为原生账号实时目录，不再使用旧 CodeBuddy 23 项静态表。

客户端内置基于真实代理流量的用量统计模块（`internal/usage`），采用纯 Go `modernc.org/sqlite` 实现无 CGO 依赖的本地持久化。

- **数据库位置**：位于数据目录下的 `data/usage.db`（跟随 `--data-dir`，默认 `%LOCALAPPDATA%\XiaoTao\data\usage.db`）。开启 WAL 模式、串行写入及有界批量提交。
- **保留策略**：
  - 请求明细表（`request_records`）：保留最近 7 天滚动周期内已结束的请求记录，启动及每日自动清理一次；不记录提示词、回复正文与用户凭据。
  - 每日用量汇总表（`daily_usage`）：长期保存，每日一条记录，永不滚动清理。
  - 重启恢复：启动时自动扫描此前未终结（`pending`/`streaming`）的遗留记录并标记为“中断”，保留已确认的用量数据。
- **统计口径**：
  - 统计开始日期：首次启动时在 `usage_meta` 表记录 `tracking_started_date`，用于在年度热力图中区分“未开启统计的历史”与“当天零用量”。
  - Token 计算：总 Token = 输入 Token + 输出 Token。缓存命中包含在输入 Token 中，不重复累加。
  - 缓存字段归一化：各上游缓存字段名不统一，Provider 层统一映射为 `cached_tokens` 并回填 `prompt_tokens_details`（Trae 用 Anthropic 风格的 `cache_read_input_tokens`/`cache_creation_input_tokens`，WorkBuddy 与 Qoder 用 `prompt_tokens_details.cached_tokens`，Codex 用 Responses 的 `input_tokens_details.cached_tokens`，Antigravity 用 `cachedContentTokenCount`）。上游明确报 0 时记 0，未报任何缓存字段时保留空值。Trae 自 2026-10-27 起可能在真实命中时仍通过 SSE 报 0；当 SSE 缓存明细缺失或为 0 时，客户端会短时查询本次上游会话的商业账单，仅在输入与输出 token 精确匹配时补回缓存读取和写入数，否则保留原值。查询失败、超时、账单尚未落库或 token 不匹配时不会猜测缓存命中。
  - 缺失与未知：上游未提供或无法解析的指标以空值（—）展示，不伪装或估算为零；缺失情况在每日汇总中单独计数。
  - 日界线：固定采用 `Asia/Shanghai` 时区。请求数归入发起时的开始日期，用量增量归入收到上游确认数据时的日期（跨午夜请求按此规则精确切分）。
  - 输出速率：已确认输出 token ÷ 首输出后经过时间的平均值（tok/s），流结束后冻结；不足 50ms 或无输出 token 时显示“—”。
- **管理接口与推送**：
  - `GET /api/dashboard`：返回版本信息、启动用量、今日与累计汇总、最近三条请求、进行中列表及年度热力图。请求摘要携带账号 ID，最近请求和进行中列表结合账号列表显示别名或昵称。
  - `GET /api/dashboard/events`：SSE 增量实时推送，建立连接时发送完整快照，后续最多每秒 4 次合并推送，提供 15 秒心跳。断线重连重新获取完整状态，通过版本号避免旧数据覆盖。离开页面自动断开。
  - 仪表盘快照先复制服务状态，再在服务锁之外读取每个进行中请求，避免与请求用量更新互相等待。前端首屏请求 10 秒超时；若 SSE 已返回快照，即使普通首屏请求尚未结束也直接退出 loading。
- **实时请求浮窗**：桌面壳提供独立小窗（`--hud-window`）展示最多三条请求的账号、模型、已确认输出速度、状态和耗时，并始终显示今日 Token 与请求次数；空闲时明确显示当前空闲。小窗逻辑尺寸为 260×170，通过标题区域拖动，不依赖主窗口，主窗口关闭后仍可继续保留；直接关闭小窗会同步关闭服务端开关。托盘右键菜单提供“打开浮窗／关闭浮窗”开关，仪表盘继续使用应用级快照与 SSE；数据口径一致，上游未提供 token 时显示“—”，不做估算。浮窗使用深色背景、今日输入输出统计和紧凑请求列表，宽度不足 250px 时隐藏账号名；独立小窗铺满原生窗口；去除原生边框后重新计算客户区并同步 WebView 尺寸。桌面壳最终外观和拖动手感仍需新包人工复核。
- **已知限制**：
  - 第一版不包含全量请求历史查询页，仅展示最近三条请求及超过三条时的进行中展开列表。
  - 依赖上游模型接口返回的真实 token 数据，若上游仅在流结束时返回 usage，则本次启动和今日用量在流结束时更新。

config.json 保留底层基础配置接口，当前页面不提供配置表单；runtime.json 保存临时地址、进程号和管理令牌（不要分享该文件），正常退出会删除；运行日志按业务模块拆分为 5 个独立子目录（`client`、`proxy`、`agent`、`auth`、`usage`），写入 `logs/<module>/<module>-YYYY-MM-DD.log`，跨天自动轮换并保留 14 天滚动历史（旧版单文件日志自动归档至 `logs/archive/`）；支持通过环境变量 `XIAOTAO_LOG_LEVEL`（debug/info/warn/error，默认 info）调节日志级别；跨层通过 `req_id`、`chatcmpl-` 及 `session_id`/`run_id` 串联追踪，严格遵守隐私红线（不记录用户消息正文、工具调用详细参数与完整结果，敏感 Token 统一经 `logging.Redact` 掩码）。logs 目录跟随 `--data-dir`。webview 目录保存窗口浏览器数据。账号元数据保存在 accounts/accounts.json，上游凭据经 Windows DPAPI 保护后存放在 accounts/keys 下。

## 已验证与限制

接口测试覆盖配置保存与重载、损坏配置保留、跨源写入与非法 Host 拒绝、页面资源及未带代理密钥的模型接口拒绝。密钥环测试覆盖 DPAPI 保护密钥的跨实例恢复。

Windows 实际进程验证通过：服务启动、重复服务拒绝、配置更新、运行文件清理、WebView2 窗口打开、关窗后服务保留、重新打开复用服务，以及退出后窗口进程结束。

当前压缩构建约 8.2 MiB，不含 Chromium 和 WebView2 运行时。使用海洋深色页面，水滴精灵图片用于页面、窗口、托盘及 EXE 图标；图标保留原始水滴造型，由共享渲染器收紧透明边距并对小尺寸做抗锯齿采样；窗口与托盘按系统 DPI 分别生成大小图标，EXE 包含 16–256px 的九档图标。构建脚本先运行 `go run ./tools/icon` 生成 `dist/icon/app.ico`，再使用固定版本 go-winres 生成 Windows 资源。系统缺少 WebView2 的浏览器回退分支尚未在缺少运行时的机器上实测。当前页面已清理为设计基础版，保留顶部导航和空内容区，临时仪表盘、介绍、调试信息及配置表单已移除。

/v1/models 与 /v1/chat/completions 已接入 Trae 国内版账号反代；Trae 目录解析 `context_window_tokens.dev`（普通窗口）和 `reasoning_effort_config.options`（归一化为内部档位），请求侧按模型档位翻译为原生拼写（light/extra_high 等）。目录条目带更大窗口的 `__max` 明细时，会生成独立的 `-max` 变体模型（如 `trae/deepseek-v4.1-flash-max`），请求时改用 `__max` 上游名并携带 `user_message_context.model_info.prompt_max_tokens`，对应 Trae 的“更大上下文 (Max)”模式。WorkBuddy 账号接入后模型 ID 需带 `workbuddy/` 前缀（如 `workbuddy/auto`），上游使用标准 OpenAI 消息格式，支持流式输出、工具调用（含 DSML 文本工具调用解析）、reasoning 与 usage 统计。Antigravity 账号接入后模型 ID 需带 `antigravity/` 前缀（如 `antigravity/gemini-3.6-flash`），上游为 Gemini 原生协议，支持流式输出、工具调用（含 thoughtSignature 缓存回传）、reasoning_effort 档位映射（low/medium/high/xhigh/max）与 usage 统计；同来源账号在首个语义事件前遇 429/403 会短冷却并切换下一个，已提交的流不会重放。聊天路由按模型前缀确定来源，再按启用账号的当前顺序选择；已知额度用完的账号会被跳过，额度数据缺失或刷新失败不阻塞调用。Qoder 有免费模型，额度不消耗，零额度不作为跳过依据。裸模型名兼容按 Trae 处理。聊天流空闲 300 秒或总时长 30 分钟未完成会自动断开；Antigravity 流式空闲 90 秒。需要页面“账号与配额”中生成的代理访问密钥；模型没有可用的已启用账号时返回明确错误。真实 Trae 和 Antigravity 账号的登录、配额与调用链路仍需人工验收。管理接口仅面向本机原型，同源校验不构成对其他本机进程的隔离。尚未实现安装更新、崩溃自动恢复、伙伴与工作流、自定义 API 接入及完整历史查询。浏览器单独运行模式不创建桌面托盘。

顶部不再显示导航。启动后默认进入小涛 Agent，左下角显示“仪表盘 / 账号与配额”入口，不再为 Agent 单独保留导航项；Agent 会话栏为入口预留底部空间。仪表盘和账号与配额作为全宽二级页面打开，此时隐藏左侧栏和左下工作空间导航，窗口标题栏左上角提供“返回小涛”，正文不再占用一行返回栏；回到首页后恢复入口。窄窗口下首页入口收成图标栏，二级页仍保留左上返回按钮；主题切换位于右上角三个点菜单，仅桌面环境显示窗口控制按钮。

Agent 工作台使用水滴状态精灵和 Lucide 线性图标，布局和响应式样式位于 `frontend/src/features/agent/`。会话栏、消息区、输入区组成固定高度工作台：长对话只滚动消息区，输入区始终留在视口内；执行步骤收进可展开的过程面板，运行和停止状态共用同一套水滴动效。深海主题下，所有页面共用延伸至半透明标题栏的海底背景；浅海主题使用雾白渐变背景，海洋科技色令牌和按钮、导航、卡片、浮窗的统一配色状态集中在 `frontend/src/ocean-tech.css`；仪表盘和账号卡片采用深色半透明底以保证可读性，左下入口与三个点菜单均有展开、焦点和减少动态效果状态。

## 小涛 Agent

支持多个会话同时运行：执行时可切换、新建对话，后台会话继续接收流式事件，侧栏显示“运行中”，停止只作用于当前会话。草稿（包括引用）、模型选择及滚动位置按会话保存在当前页面内存中，刷新页面不保留这些临时状态；刷新或关闭窗口仍可能中断流式请求，未增加断线恢复能力。同一会话仍只能执行一轮消息。

多个会话共享所选目录，不自动创建 worktree，不弹同项目并发提示。每次模型请求刷新同项目其他运行任务的有界标题摘要（作为不可信参考数据），允许正常修改同一文件。write_file 覆盖或追加已有文件前必须在本轮 read_file；读取或写入后保存整个文件的内容摘要，后续写入检测到变化或删除时拒绝操作，模型重读合并，无法合并才告知用户。同进程文件写入的检查与写入串行执行，读取之间可并行；外部编辑器、命令和脚本不参与该锁，无法保证它们在检查和写入间的原子隔离。多个高危操作的确认弹窗排队并标明会话。

回归入口：在 frontend 运行 `node --test tests/agent-concurrency.browser.test.mjs`；使用隔离的本地 SSE 服务验证双会话、后台回复、独立停止、草稿和确认队列，不访问真实账号。桌面 WebView2 和真实账号并发限流仍待新包人工验收。

Agent 输入框粘贴时，如果整段内容被 ` ```markdown ` 或 ` ```md ` 围栏包裹，会去掉最外层围栏并按 Markdown 格式插入；其中的代码块仍会保留。单行 Windows 路径按原文插入，不自动转换成链接；普通网址仍可识别为链接。带代码样式 HTML 的粘贴按纯文本插入，使用硬换行保留行结构；在代码块内的粘贴沿用原有行为。可在 `frontend` 运行 `node --test tests/markdown-paste.browser.test.mjs` 验证，默认使用 `/usr/bin/chromium`，也可通过 `XIAOTAO_TEST_BROWSER_PATH` 指定浏览器。

输入框支持 `@` 引用其他对话：默认搜索当前项目，可切换到所有项目；支持标题搜索、方向键、Enter、Escape 和关闭按钮。引用标签保存在 Tiptap inline node 中，发送时提交结构化会话 ID，正文保留可读的 `@标题`；只放引用标签也可以发送。一条消息最多引用 5 个对话，来源只读取用户和助手文字，不计工具原始输出；单个来源最多 64 KiB，所有来源合计 128 KiB。发送时冻结来源边界，来源后来更新时消息显示“有新内容”，旧消息仍使用旧快照；来源删除后已保存摘要仍可查看。正式版与 UAT 的引用和快照数据继续隔离。

首版摘要是对冻结文字的确定性截取，不额外请求模型；模型上下文只在当前用户消息前注入一次引用摘要，不重复发送旧引用全文。`read_conversation_reference` 只能读取当前消息直接引用的快照，并按关键词返回有界片段。浏览器回归入口为 `node --test tests/agent-references.browser.test.mjs`；真实 WebView2 的输入法、浮层和长对话仍未人工验收。

聊天消息按 Markdown 展示，支持段落、列表、链接、表格和代码块；长代码可横向滚动。
任务运行中，小涛头像会按最近状态切换：理解时思考，读取/搜索时扫描，写入时动笔，执行命令时显示工具状态；头像旁的短气泡显示当前理解或进展。气泡最多显示两行，流式文字超过两行时自动跟随到最新尾部；输出期间有轻微流动高光和闪烁光标，减少动态效果时关闭。下面固定展示最新四条“中文摘要 + 工具动作”，只轮换内容，不允许在四行窗口里手动滚动。完整记录通过“查看思考过程”在右侧抽屉查看，不改变对话区宽度。模型私有推理不会直接展示；进度来自模型主动输出的文字和实际工具活动，不为展示进度额外请求模型。模型在工具调用之间产生的说明只进入过程轨迹，不作为聊天正文重复显示；每轮正文只保留最后一次正式回答。
任务结束后，不再保留上方独立轨迹或本轮总结块。正式回答使用自己的完成头像，头像右侧一行显示耗时、读取文件数、工具调用数和“查看过程”，下一行直接进入结论正文。输入框工具条在访问模式旁显示最近一轮估算上下文用量，模型窗口已知时显示百分比，未知时只显示已用 token，不伪造上限；点击可展开详情浮层，直观查看系统指令、工具定义 Schema、对话消息、工具调用输出、引用和图片的分类估算占比及剩余空间，并展示供应商返回的真实输入、输出、缓存命中 Token 与请求轮次。在构建模型请求时，旧工具结果自动执行确定性精简（保留退出码、报错首尾与回查标记），并通过只读的 read_historical_tool_result 提供受限回查能力，原始会话历史完整保留；长会话达到 80% 窗口阈值时自动压缩较早历史并派生保存结构化工作摘要，确保长任务安全持续执行。设计与验收见 [小涛 Agent 上下文瘦身与长会话优化](../docs/plans/2026-11-08-agent-context-pruning.md)。
每轮状态为 working → completed / failed / canceled。执行中气泡以两行高度渲染 Markdown，保留最新四条过程；回答结束后同一个气泡展开完整正文，思考框收起，底部保留一行耗时、文件数和工具次数，点击摘要可查看完整过程。不再要求模型切换阶段，不增加二次回答请求。停止和断流保留部分文字并标明真实状态；历史直接展开，减少动态效果时取消过渡。设计与验收见 [结果气泡展开](../docs/plans/2026-11-07-agent-result-expansion.md)。
向上翻阅、距离底部至少 80px 时，输入框正上方居中显示“回到底部”圆形箭头按钮；点击或键盘激活后平滑返回最新消息，接近底部自动隐藏。系统启用减少动态效果时直接滚到底部。
浮层展开和收起有短暂过渡，并遵循系统减少动态效果设置。

常用模型的 ID 和显示名称保存在当前客户端的本地浏览器存储中，重新进入时直接使用缓存；只有打开 Agent 设置才加载完整模型目录。目录加载失败或暂时缺少某个已选模型时保留原选择，实际调用仍取决于账号和模型是否可用。

侧边栏标题显示当前视图，点击右侧切换图标可选择“按项目查看”或“按会话查看”，选择会自动保存。侧边栏支持“项目”和“会话”视图：项目视图按目录分组，未选择项目的会话放在底部“最新”；会话视图按最近更新时间排序。会话可经确认后删除，消息和执行记录同时删除；运行中的任务须先停止。删除会话、移除账号和重新生成 API 密钥共用随主题切换的确认弹窗，支持键盘操作和 Escape 取消。旧版 JSON 迁移备份仍保留。
项目视图中点击项目名或“最新”可展开、收起对应会话列表，默认展开。项目行不显示三角箭头，悬停或键盘聚焦时显示三点菜单和新会话图标；新会话会检查目录并自动填入该项目。已保存项目里没有会话时，项目行仍保留，展开后显示“暂无会话”，仍可通过旁边的按钮新建会话或在输入框的项目选择中选中它。三点菜单支持重命名项目显示名和在 Windows 资源管理器中打开目录；重命名会同步保存同目录下所有会话的项目显示名，不修改目录名称、消息或排序，项目中有运行会话时须先停止。删除项目只移除项目分类，不会删除会话：项目内的会话回到“最新”分组继续保留消息和执行记录，工作目录不变；再次保存同一目录时，这些会话回到该项目分组。触屏入口始终显示操作按钮。

在小涛回复中选中文字后可点击“引用”，支持同时引用多段文字；输入框显示紧凑标签，悬停可查看内容。发送前原文带有高亮和编号，点击编号可编辑引用文字、填写对应回复或移除；发送后标记消失。引用作为带来源说明的 Markdown 文本随消息保存并发送给模型。

Agent 页首屏为简洁的聊天空状态，使用戴耳机、拿奶茶的透明底小涛主视觉，仅保留“今天想做什么？”文案；发送第一条消息时创建会话，输入区使用 Tiptap。主视觉按比例限制宽度并随窗口和可用高度缩小，窄屏不遮挡文案或输入框。普通段落按 Enter 发送、Shift + Enter 硬换行、Ctrl/⌘ + Enter 强制发送；列表内按 Enter 或 Shift + Enter 新建下一项，空项再回车会退出当前层级；标题、引用和代码块内优先保留编辑行为，代码块按编辑器规则换行和退出。发送内容按 Markdown 序列化，列表、标题、引用、粗体、斜体、删除线、链接、行内代码、代码块和分割线不会在发送时丢失结构。行内代码支持先输入一对反引号、再填写内容，光标移到末尾按空格后转换样式。输入框外左上角管理项目：项目弹窗通过系统文件夹选择目录，并可设置项目显示名；项目显示名随会话保存。点“使用这个项目”即校验目录、切换工作目录并把该项目保存到侧栏项目列表，不再区分“只选择”和“保存项目”两个动作。桌面窗口使用 Windows `IFileOpenDialog` 只选目录，并通过原生窗口事件异步回填；本次修复后桌面交互仍待验收。输入框右下角只保留 Agent 设置中勾选的常用模型；Agent 设置弹窗按来源列出完整聚合目录、支持搜索与批量勾选，选择保存在本机浏览器存储中。浏览器入口无法获取本机文件夹路径，请在桌面客户端选择项目。任务优先使用已启用账号中聚合出的完整模型 ID，不默认伪造可用模型。没有模型时页面会引导到“账号与配额”。可在 `frontend` 运行 `node --test tests/agent-empty.browser.test.mjs` 检查图片加载和桌面、窄屏布局；桌面壳实际效果仍待人工验收。

首版支持：

- 多会话可同时读写项目文件、字面搜索和运行非交互式命令；Windows 下后台 PowerShell 不弹出控制台窗口，输出仍显示在执行过程中。
- 工作目录作为默认位置，可跨目录读写；输入框左下角全局切换安全模式和完全访问。安全模式对常见高危命令和覆盖较大文件弹出确认，完全访问不逐项确认；支持命令超时及输出上限。
- 模型工具循环没有固定轮数上限，在最终回答、用户停止或实际错误时结束；工具结果完整回传。任务开始显示等待提示，直接发起正式模型请求；不为复述需求、推理转述或阶段检查点额外请求模型。允许重复调用工具以支持轮询。
- 同一轮中连续的 read_file、list_files、search_files 最多四个并发执行，完成后按模型给出的顺序回传结果；写入、命令和 MCP 调用是顺序边界，不与前后读取并行。单个读取失败不会阻止同批其他读取，停止后不再启动新的读取。
- 会话、消息和工具活动保存在数据目录的 agent/agent.db（SQLite，未加密）；旧版 agent/sessions/*.json 首次读取时事务导入并保留原文件。正式版与 UAT 独立存储。
- 切换页面时保留 Agent 工作台和当前会话；会话列表先加载摘要，选择会话时分批读取最近消息与执行记录，向上滚动加载更早历史，模型目录独立加载。
- 项目可选；未选时使用数据目录的 agent/workspace/，与数据库和账号目录分开。模型调用通过本地 /v1/chat/completions，自动使用当前代理密钥（轮换后无需重启），继续使用账号路由和用量统计。
- 新会话中选定项目后，可点目录旁的关闭按钮清空选择；发送首条消息创建会话后，工作目录不可更改。未选项目的会话在项目视图中归入“最新”。
- 粘贴图片要求当前模型声明支持视觉输入；会话历史已含图片时，即使旧图尚未加载到当前分页，也不能切换到纯文本模型继续发送。服务端从完整会话再次校验，前端用轮次统计中的图片标记提前禁用发送。

### 完整小涛规则

Agent 已内置完整 `xt-skills/xiaotao` Core。新会话首次发送注入完整 SKILL.md，后续使用精简守卫，参考文档与脚本按当前步骤读取；已有会话下次发送也能访问完整 Core。资源在当前环境 Agent 数据目录的 `core/<资源摘要>/` 下释放，正式版与 UAT 独立。

每次发送都会内联「阶段保存契约」：Core 内 `scripts/save_progress.py` 的绝对路径、stdin JSON 字段（`request_id`、`topic_id`、`title`、`summary`、`details`、`validation`、`next_steps`）、触发时机与跳过条件。模型无需再读 `references/progress-saving.md` 即可在交付前保存一次阶段记忆；详细规范仍以该文档为准。

命令执行在 Windows 上先注入 UTF-8 前置：PowerShell 的 `[Console]::OutputEncoding` 和 `$OutputEncoding` 都设为无 BOM 的 UTF-8，内置搜索按 UTF-8 读取，子进程带 `PYTHONIOENCODING=utf-8`。默认控制台代码页 936 时，中文经管道传给 `save_progress.py` 会在到达脚本前就变成问号，2026-11-07 的两条记忆记录因此损坏；文件读取仍沿用系统默认编码，避免破坏 GBK 旧文件；需要按 UTF-8 读文件时要显式传 `-Encoding UTF8`。回归测试见 `internal/agent/encoding_test.go`。

这不会增加独立 Worker、Hook 或后台恢复能力；不支持的能力会明确降级。记忆保存脚本需要本机 Python，不保证仅注入规则就已完成记忆保存。构建前自动从唯一源目录刷新资源；开发时改动 Skill 后运行 `node tools/bundle-core.mjs` 或 `go generate ./internal/agent`。新功能需要运行更新后的客户端生效，当前已启动实例不会热更新。

### 本地 Skills

在 **Agent 设置 → Skills 技能** 添加技能目录，点击“扫描目录”查看名称、描述和诊断，再保存。支持直接含 `SKILL.md` 的文件夹，或其一级子文件夹中的技能；可填写绝对路径，桌面客户端还支持选择目录。草稿扫描不保存、不执行脚本；切换设置页签保留草稿，关闭后重新打开读取已保存配置。可按目录或单个技能启用/禁用。

`SKILL.md` 需要 UTF-8 和 YAML front matter：

```markdown
---
name: code-review
description: 用户要求代码评审时，检查实际缺陷并给出文件位置和验证方法。
---

先阅读相关代码和测试，再报告有证据的问题。
```

保存后从下一次发送消息生效，包括已有会话；正在执行的消息使用原索引。每次发送重新读取已启用目录，只把无冲突技能的名称、描述和绝对路径加入模型上下文。可以直接说“用 code-review 技能评审这个改动”；模型需先通过 `read_file` 读取技能全文，再按需读取相对引用。匹配与实际遵循依赖模型，目录发现和摘要注入由程序完成，不代表所有技能已加载或已执行。

不同文件的同名技能（忽略大小写）均标为冲突，不自动选一个；停用其中一个再扫描即可。重复指向同一实际文件的目录只发现一项；`xiaotao`/`小涛` 同名技能不能替代内置 Core。缺少文件、错误元数据和无法访问目录会显示诊断，其他有效技能可继续使用。扫描不跟随指向所选根目录外的技能链接；需要使用时直接添加其实际目录。

配置保存在本环境数据目录的 `agent/skills.json`，正式版和 UAT 独立，不从另一环境或项目自动导入。只存路径和禁用 ID，不复制第三方技能正文；本地文件修改在下次发送重新发现。移除目录不会删除磁盘上的技能。禁用只控制发现与使用提示，不是文件权限隔离；当前用户仍可访问对应文件。技能不能扩权或改变访问模式，执行脚本沿用现有命令确认；Python、Node 等依赖按实际技能要求检查，不自动安装。小涛身份与 Core 始终保留。

扫描上限：16 个目录；每目录最多 512 个直接子项；每次最多 128 个技能、256 个候选文件；最多展示 64 条诊断，其余有遗漏提示。单文件最多 128 KiB，front matter 最多 16 KiB，名称最多 100 字符、描述最多 1024 字符。模型索引数据最多 64 KiB，达到上限会注明遗漏，请减少启用范围。配置损坏会明确报错，不能被当成没有技能。

本期没有在线市场、下载、自动安装/更新或自动依赖安装。管理 API：GET/PUT `/api/agent/skills`、POST `/api/agent/skills/scan`，均校验同源。前端回归：`node --test tests/skills-settings.browser.test.mjs tests/mcp-settings.browser.test.mjs`；自动化使用隔离测试目录和合成 API，不代表真实模型或桌面目录选择已验收。设计与验收见 [本地 Skills 计划](../docs/plans/2026-11-06-client-local-skills.md)。

## Agent 网页操作与调试（MCP）

在“Agent 设置 → MCP 工具”中添加服务，填写名称、启动命令和参数（每行一个，不加 shell 引号），可启用、禁用或删除服务。Chrome 浏览器 MCP 是默认启用的内置功能，无需手动添加，不能删除、禁用或修改启动配置；已有配置中的同名浏览器条目自动使用内置配置。需要本机安装 Node.js 与 Chrome，首次测试或使用时会下载 npm 包。

“测试连接”使用当前草稿启动服务、初始化并读取工具列表，不调用工具、不保存草稿；可取消，整体限时 35 秒（浏览器请求 40 秒兜底）。“保存 MCP 配置”写入当前环境数据目录的 `agent/mcp.json`，下一次任务生效，无需重启客户端；已有任务保持原连接。正式版与 UAT 独立保存，配置不会从项目自动读取，也不会导入另一环境的 MCP 配置。命令以当前用户身份启动，只配置可信服务；安全模式仍会逐次确认模型发起的 MCP 工具调用。

兼容原有环境变量入口：没有本地 `agent/mcp.json` 时读取 `XIAOTAO_MCP_CONFIG`；设置页会显示来源，保存后使用本地配置，不回写外部文件。本地空配置也优先于环境变量。也可以复制 `mcp.example.json` 到自己管理的配置路径，在 PowerShell 中启动客户端：

```powershell
$env:XIAOTAO_MCP_CONFIG = 'C:\你的目录\mcp.json'
& '.\dist\xiaotao.exe'
```

示例通过 `npx.cmd` 启动 Chrome DevTools MCP；非 Windows 系统使用 `npx`。没有本地配置且未设置环境变量时，仍加载内置浏览器工具。本地空配置只清空自定义服务，不能移除内置浏览器。每个服务支持 `command`、`args` 和可选 `disabled`；本期不支持服务环境变量或 HTTP 连接。

每次任务启动服务、完成 MCP 初始化并发现工具，将 JSON Schema 注册到模型；工具结果携带原调用 ID 回传，沿用过程事件。安全模式每次外部工具调用请求确认，完全访问模式直接执行。停止任务或工具超时会终止该服务；任务退出清理进程。初始化和发现每次请求限时 30 秒，工具执行限时 120 秒，单条协议消息上限 8 MiB。服务错误使任务明确失败，不静默忽略。

当前仅支持 stdio 与文本形式工具结果；图片结果保留 MCP JSON，尚未转成模型视觉消息；不支持 HTTP MCP、服务端交互请求或 Windows 桌面控制。浏览器登录态和进程由所选 MCP 服务管理。可要求 Agent 打开测试网页、查看 Console 与 Network 后修改项目并复查。2026-11-05 用户实测反馈已连接 32 个浏览器工具，可打开 example.com，并返回页面标题与控制台检查结果；Network、安全模式拒绝、停止及桌面壳细节仍待专项验收。
