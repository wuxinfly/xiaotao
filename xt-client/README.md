# XiaoTao 客户端

## 外观主题

右上角“浅海 / 深海”按钮可即时切换主题：深海沿用原有海洋暗色，浅海使用雾白背景、浅蓝灰卡片和深青正文。Agent、仪表盘、账号页、弹窗与菜单共用主题；选择保存在当前环境浏览器存储 `xiaotao.theme` 中，重开后恢复，未选择时默认深海。独立请求浮窗保留主题同步机制，浮窗界面在两种主题下均使用深色；正式版和 UAT 使用不同端口，选择各自保存。原生启动动画不参与网页主题切换。

前端验证：在 `frontend` 执行 `node --test tests/theme.browser.test.mjs`，使用合成数据拦截全部 API，覆盖键盘切换、刷新恢复、Portal 弹窗、浮窗同步、窄窗口入口及主题模块的存储不可用降级。桌面壳实际效果仍需人工验收。设计与验收记录见 [浅海主题](../docs/plans/2026-11-03-shallow-sea-theme.md)。

页面和内层区域采用细滚动条：鼠标移入区域或滚动时显示，移出且停止滚动约 0.9 秒后自动隐藏，仍可使用滚轮、触控板和键盘滚动。

## Codex 接入（2026-11-01）

账号与配额 → 添加账号 → 选择 Codex（ChatGPT）后，在浏览器完成 OAuth 2.0 PKCE 授权，也可以通过“导入 Codex 登录态”直接粘贴本机 ~/.codex/auth.json 凭据。授权默认监听本地 http://localhost:1455/auth/callback，端口冲突或未自动跳转时支持手动粘贴回调完整 URL 或 code 参数。账号凭据经 Windows DPAPI 加密保存，刷新自动处理 refresh token 轮换。

模型支持静态底表与账号目录实时拉取（GET /models?client_version=0.159.0），默认包含 gpt-6.1-sol、gpt-6-astra、gpt-6-sol、gpt-6-luna、gpt-5.6-sol 等主力模型，调用 ID 带 codex/ 前缀（如 codex/gpt-6.1-sol）。

已实现 OpenAI Chat Completions 双向投影（Chat 请求转 Responses 协议，Responses SSE 增量折叠为 Chat 流式与非流式结果），支持 instructions / system 拼接、图片输入、工具调用、reasoning 内容折叠及真实 token usage 统计。额度查询接入真实 /backend-api/wham/usage 接口，按 5小时/周窗口展示百分比额度与重置时间。

详细记录见 [Codex 实施计划](../docs/plans/2026-11-01-codex-proxy.md)。

## Qoder 接入（2026-11-01）

账号与配额 → 添加账号 → 选择 Qoder 国内版或海外版后，在浏览器完成设备授权。授权窗口为 10 分钟，可取消、复制链接或重新打开；账号详情支持按原区域重新登录。同 UID 在两区分别保存，凭据仍由 Windows DPAPI 加密。设备 token 刷新由聊天、模型目录和额度共用按账号加锁的入口，轮换结果不会覆盖重新登录或已删除账号。

模型从该账号上游目录获取，缓存 5 分钟；“刷新列表”强制刷新。失败时显示上次目录与错误，无历史目录则显示不可用，不用静态模型冒充账号权益。外部工具使用完整的 `qoder/<模型名>`（如目录中的 `qoder/qwen3.8-flash`），未知新模型的公开 ID 带稳定 key 摘要以避免重名。

已实现 OpenAI Chat Completions 的流式/非流式、reasoning、工具参数分片、图片内容透传、真实 token usage；上游 HTTP 或带内错误会失败，未收到完成标记的断流不会伪装成功。连接上限 15 秒、聊天空闲上限 300 秒、总时长 30 分钟，不自动重放、换号或排队重试。订阅、加购、活动资源包分别显示，标题合计已知积分；独立到期日期显示为“到期”，缺失数值保留未知。

验证边界：当前通过本地 mock、Go 回归、前端和 Windows EXE 构建；CN / Global 真实账号授权、模型权益、聊天与额度尚未实测，桌面壳交互仍待验收。自动签到、PAT/本机凭据导入、Responses/Anthropic 入口不在本期范围。详细记录见 [Qoder 实施计划](../docs/plans/2026-11-01-qoder-proxy.md)。

已实现 Windows 客户端：Go 独立本地服务、嵌入式 Web 页面、系统 WebView2 窗口及浏览器入口。模型代理已接入 Trae 国内版、WorkBuddy（国内版）与 Antigravity（Google OAuth）账号反代。小涛 Agent 已具备单任务、单项目的首版执行闭环：选择模型后即可对话；可选择项目，未选项目时使用数据目录内的默认工作目录。Agent 可以查看文件、修改代码、运行验证并停止任务。

首次使用 Agent 时，在“Agent 设置”中选择常用模型并保存，再从输入区选择模型。模型目录从启用的账号并行获取；加载失败或超时可重试，列表为空时可前往“账号与配额”检查账号。已保存的模型会保留，但实际调用仍取决于账号状态和上游可用性。

Agent 模型目录首次获取成功后缓存在当前客户端或浏览器中，重新打开设置不会自动拉取。账号或模型发生变化后，在 Agent 设置中点击“刷新模型列表”；刷新失败时保留上次缓存和已选模型。

Agent 设置中的模型按来源默认折叠，点击来源可展开；搜索时自动展开匹配的来源，清除搜索后恢复折叠。

输入区下方显示当前任务的工作目录；未选择项目时会说明使用小涛数据目录内的默认工作区。较长路径可将鼠标悬停在说明上查看完整内容。

新会话可在输入区的项目选择器中搜索并切换已有会话的项目，也可选择新的项目文件夹或使用默认工作目录。已有会话的项目不可更改；选择历史项目时会检查目录是否仍然存在。

会话列表按最近更新时间排序，并显示每个会话距今的更新时间；按会话查看时还会显示所属项目。

会话行悬停或键盘聚焦时显示三个点，点击或右键会话可打开“重命名、删除”菜单。重命名会保存到本地，删除仍需确认；运行中的会话须先停止再操作。

项目级弹窗外壳位于 `frontend/src/components/modal/ModalFrame.tsx`，样式随组件加载，提供标题、说明、内容和底部插槽，并统一处理 Portal、焦点循环、Escape 关闭及焦点恢复。Agent 设置、项目选择和会话重命名均使用该组件，底部操作按钮靠右排列。

公共弹窗优先以触发控件为缩放和位移动效的起点，也可通过 `origin` 指定视口坐标；无触发位置时从上方向下淡入。减少动态效果设置下关闭位移和缩放动画。

使用 `ModalPresence` 包裹条件渲染的弹窗，可在关闭时保留 180ms，向上偏移淡出后移除；离场期间禁止交互。

小涛每次接收消息时会读取所选工作目录根部的 `AGENTS.override.md` 或 `AGENTS.md`，优先读取非空的前者，并将内容作为项目指令发送给模型；文件须为 UTF-8，最大 32 KiB，读取失败会报错。子目录规则目前由模型按提示主动查找，不能保证自动加载；不读取项目外的全局指令，也不支持自定义备用文件名。

产品范围、分发更新规则和待定事项见[客户端总体方案](../docs/architecture/xt-client-overview.md)。

## Trae 与 WorkBuddy 签到（2026-11-01）

WorkBuddy 代理会合并完全相同的同名工具；同名工具定义不同时返回冲突错误，请客户端合并后重试。为兼容上游渠道校验，WorkBuddy 请求中的 developer 角色会转为 system；首条 system 提示词若以已知 DeepSeek Harness 或 Claude Code 身份句开头，会将该句替换为中性占位文本，其余内容保留。上游仍返回 11128 时会说明原因，并在本机运行日志记录前 20 条消息的角色、内容类型及是否包含已知身份句，不记录消息正文或凭据；实际可用性取决于上游策略。

针对具备每日签到积分的上游平台（Trae 国内版、WorkBuddy），客户端支持手动打卡与签到状态查看：
- **Trae**：针对国内区（CN）账号接入 `/trae/api/v2/ug/checkin_credits/{status,claim}`，内置稳定设备指纹派生与风控换机重试（海外账号自动跳过不请求）。
- **WorkBuddy**：接入活动状态查询 `/v2/billing/meter/checkin-activity-status` 与打卡领积分 `/v2/billing/meter/daily-checkin`。
- **操作交互**：账号卡片及详情弹窗显示打卡状态徽标，支持单个账号点击签到打卡，并在来源分组头部提供“一键打卡”批量签到。打卡成功后自动刷新账号配额。

## 构建与验证

当前验证环境为 Windows amd64、Go 1.27、Node.js 22。开发构建需要 Node.js，最终用户无需 Node.js 或 Python。前端采用 React + TypeScript + Vite，源码位于 frontend，构建产物嵌入 Go EXE。

```powershell
cd xt-client
cd frontend
npm ci
npm run build
cd ..
go test ./...
go vet ./...
./build.ps1 -Verify
```

### 不重启服务调试前端

当正式版或 UAT 正在运行、又只想调整页面样式或交互时，不要让 `build.ps1` 或 `--stop` 打断当前实例。另起 Vite 开发服务器，把 `/api` 代理到正在运行的服务：

```powershell
cd xt-client/frontend
npm run dev -- --api-port 5455
```

`--api-port` 填小涛服务的实际端口，正式版通常为 5455，UAT 通常为 5456；端口被占用时以对应数据目录下的 `runtime.json` 为准。打开 Vite 输出的地址（默认 `http://localhost:5173/`）即可。参数只接受 1–65535 的端口号，并优先于 `XIAOTAO_DEV_API`。

也可以沿用环境变量指定服务地址：

```powershell
$runtime = Get-Content -Raw "$env:LOCALAPPDATA\XiaoTao\runtime.json" | ConvertFrom-Json
cd xt-client/frontend
$env:XIAOTAO_DEV_API = $runtime.URL
npm run dev -- --host 127.0.0.1 --port 5460 --strictPort
```

打开 `http://127.0.0.1:5460/` 即可用真实账号、配额和仪表盘数据预览最新前端代码，Vite 修改后热更新。UAT 将 runtime 路径换成 `$env:LOCALAPPDATA\XiaoTao-uat\runtime.json`，并另选预览端口；不要与 5455/5456 冲突。

调试期间注意：

- 只在 Vite 代理内访问运行中的服务，`XIAOTAO_DEV_API` 必须是本机 `127.0.0.1` 地址；代理会把请求的 `Host` 和 `Origin` 改写为服务自身地址，以满足服务的同源校验。
- 预览页面的增删账号、刷新配额、轮换密钥等按钮会真实修改当前实例数据。只调样式时避免点击这些写操作。
- 不把 `XIAOTAO_DEV_API` 或临时代理配置提交到构建产物。默认未设置该变量时，开发服务器不启用代理，正式构建行为不变。
- 验证完成后关闭 Vite 进程并清理环境变量；需要让桌面窗口加载新前端时，再选择合适时机构建和重启，不能中断用户正在使用的服务。

客户端版本记录在 `VERSION`，格式为 `主版本.次版本.构建号`。正式版和 UAT 共用一个版本序列：手动打包（`./build.ps1` 或 `./build.ps1 -Env uat`）时第三位加 1，全部步骤成功后写回文件；失败不递增，并发构建不能同时使用该版本文件。版本同时注入程序及状态接口，旧版本文件不会自动删除。

AI 改代码后自行构建验证必须使用 `./build.ps1 -Verify`，UAT 验证使用 `./build.ps1 -Env uat -Verify`。验证构建沿用当前版本、不写入版本文件，输出到 `dist/verify/`，也不更新桌面快捷方式或带版本号的分发文件。

建议前两位按发布内容手动调整：出现不兼容的重大变化时增加主版本并将次版本和构建号归零；新增兼容功能时增加次版本并将构建号归零。普通修复和日常打包只增加第三位。例如将 `VERSION` 改为 `1.1.0` 后，下一次打包得到 `1.1.1`。

正式构建和 UAT 构建使用同一份源码，但环境身份在编译时注入，互不共用数据目录、端口和单实例。UAT 首次启动时会从正式版只读导入一次已登录的模型账号；代理密钥、用量、配额、配置、Agent 会话、日志和运行时状态仍分别保存：

| 构建 | 输出 | 默认数据目录 | 默认端口 | 桌面快捷方式 |
| --- | --- | --- | --- | --- |
| `./build.ps1` | `dist/xiaotao.exe` | `%LOCALAPPDATA%\XiaoTao` | `5455` | 小涛 |
| `./build.ps1 -Env uat` | `dist/xiaotao-uat.exe` | `%LOCALAPPDATA%\XiaoTao-uat` | `5456` | 小涛 UAT |

固定端口被占用时服务仍会回退到系统分配的空闲端口，实际地址以 `runtime.json` 或 `--status` 为准。`--data-dir` 显式传入时仍以参数为准。

UAT 的模型账号导入只执行一次，导入结果保存在 `%LOCALAPPDATA%\XiaoTao-uat\accounts\accounts.json`，完成标记为同目录的 `import.json`。正式版文件只读取、不写入；之后在 UAT 增删或重新登录账号都不会影响正式版。需要重新导入时，先关闭 UAT，再删除 UAT 的 `accounts` 和 `keys` 目录；不要删除正式版数据。会轮换 refresh token 的来源（如 Codex、Qoder）在正式版和 UAT 同时刷新时可能使另一侧登录态失效，双开测试时优先使用不会轮换的来源，或在一侧测试结束后重新登录。

双击 dist/xiaotao.exe 自动启动隐藏服务进程并打开桌面窗口；未安装 WebView2 时尝试用默认浏览器打开。不安装运行时，不主动写入注册表。当前 EXE 是运行程序，尚不是带版本检查的安装启动器。

build.ps1 构建成功后会在当前用户桌面创建或更新“小涛”快捷方式，指向本仓库 dist/xiaotao.exe；移动 EXE 后需重新构建更新快捷方式。桌面窗口和启动封面使用 Windows 11 系统小圆角；启动封面由原生窗口通过 GDI 帧流渲染 startup.mp4 动画。封面不全局置顶，作为主窗口的 owned window 覆盖初始化内容；主窗口保留正常可见性，让 WebView2 正常加载和绘制。首屏字体与图片处理完成并满足最短动画时长后，关闭封面露出主界面。用户已切到其他应用时在后台完成交接，不抢焦点。原生窗口和 WebView2 默认背景均为深色；15 秒未收到首屏就绪信号时兜底交接，页面加载失败仍需另行处理。无外部依赖、无安全下载弹窗、无跳过按钮；托盘恢复、页面刷新及浏览器入口不显示启动动画。

## 使用与生命周期

- 默认数据目录：正式版为 LOCALAPPDATA/XiaoTao，UAT 版为 LOCALAPPDATA/XiaoTao-uat；使用 --data-dir 指定其他目录。UAT 仅首次启动时从正式版导入模型账号登录态，其他数据不共享。
- --browser：启动或复用服务，在默认浏览器打开页面。
- --service：只运行服务，主要供启动入口内部调用。
- --status：输出运行服务地址；GUI 构建不便查看标准输出时，可读取数据目录中的 runtime.json，或使用 go run ./cmd/xiaotao --status。
- --stop：停止该数据目录对应的服务。
- 自绘标题栏提供拖动、最小化、最大化和关闭；最大化按当前显示器工作区适配，不会越过屏幕边缘或压住任务栏。关闭收起到系统托盘，服务继续运行。
- 最小化左侧的“更多”按钮支持悬停或点击展开菜单，可用资源管理器打开安装目录（当前 EXE 所在目录）和当前实例的数据目录（遵循 --data-dir）；支持方向键选择及 Escape 关闭，仅桌面窗口显示。
- 托盘双击恢复窗口，右键提供打开小涛、在浏览器打开、退出小涛。--stop 同样停止服务及窗口。
- 同一数据目录仅一个服务和一个桌面窗口；正式版和 UAT 版使用不同数据目录与锁，可同时运行；已有窗口时再次打开尝试恢复窗口。
- 启动入口对同一数据目录使用独立启动锁；双击、托盘恢复或并发启动时，健康服务会被复用，不会因启动竞争把正常单实例锁冲突误报为服务启动超时。
- 仅监听 127.0.0.1 回环地址，不向局域网提供服务；正式版优先使用 5455，UAT 版优先使用 5456，端口占用时自动回退到空闲端口。

## 模型用量与仪表盘

在“账号与配额”的各接入来源旁点击“查看模型”，会在弹窗内切换账号查看模型名称与完整调用 ID、复制 ID 或刷新目录。弹窗支持 Escape 和点击遮罩关闭，关闭后焦点回到“查看模型”。列表区分实时、内置、合并与上次目录。Trae 兼容对象/字符串元数据并过滤内部条目，保留上游原始名称。Antigravity 实时发现公开对话模型并合并已验证底表，动态模型携带档位路由；暂不收录生图模型。刷新失败保留上次账号目录，无历史快照时回退内置表。WorkBuddy 使用内置目录。目录不保证当前账号已获模型权限，实际调用仍取决于来源匹配、权限和额度。页面通过同源 `POST /api/proxy/models?accountId=<id>` 获取指定账号目录，不影响代理路由。
接入来源卡片的标题区域可点击展开或收起，右侧操作按钮独立使用。点击账号打开详情，可设置最多 40 个字符的备注；账号卡片、模型目录和用量展示优先显示备注，清空后恢复显示原账号昵称。备注保存在当前环境的账号数据中。

模型目录：页面刷新与 `/v1/models` 按启用账号聚合，同一来源模型 ID 去重。Trae 优先读取实时目录，过滤关闭、隐藏、自定义和 builder 条目，成功后不再混入静态表；请求最多 10 秒，失败或空目录优先沿用账号上次成功目录，无快照时回退静态表。WorkBuddy 静态表已按 buddy-proxy 的 2026-11-01 配置同步为 23 项，含 `workbuddy/mimo-v2.6-pro`，其真实账号调用仍待验收。

客户端内置基于真实代理流量的用量统计模块（`internal/usage`），采用纯 Go `modernc.org/sqlite` 实现无 CGO 依赖的本地持久化。

- **数据库位置**：位于数据目录下的 `data/usage.db`（跟随 `--data-dir`，默认 `%LOCALAPPDATA%\XiaoTao\data\usage.db`）。开启 WAL 模式、串行写入及有界批量提交。
- **保留策略**：
  - 请求明细表（`request_records`）：保留最近 7 天滚动周期内已结束的请求记录，启动及每日自动清理一次；不记录提示词、回复正文与用户凭据。
  - 每日用量汇总表（`daily_usage`）：长期保存，每日一条记录，永不滚动清理。
  - 重启恢复：启动时自动扫描此前未终结（`pending`/`streaming`）的遗留记录并标记为“中断”，保留已确认的用量数据。
- **统计口径**：
  - 统计开始日期：首次启动时在 `usage_meta` 表记录 `tracking_started_date`，用于在年度热力图中区分“未开启统计的历史”与“当天零用量”。
  - Token 计算：总 Token = 输入 Token + 输出 Token。缓存命中包含在输入 Token 中，不重复累加。
  - 缓存字段归一化：各上游缓存字段名不统一，Provider 层统一映射为 `cached_tokens` 并回填 `prompt_tokens_details`（Trae 用 Anthropic 风格的 `cache_read_input_tokens`/`cache_creation_input_tokens`，WorkBuddy 与 Qoder 用 `prompt_tokens_details.cached_tokens`，Codex 用 Responses 的 `input_tokens_details.cached_tokens`，Antigravity 用 `cachedContentTokenCount`）。上游明确报 0 时记 0，未报任何缓存字段时保留空值。
  - 缺失与未知：上游未提供或无法解析的指标以空值（—）展示，不伪装或估算为零；缺失情况在每日汇总中单独计数。
  - 日界线：固定采用 `Asia/Shanghai` 时区。请求数归入发起时的开始日期，用量增量归入收到上游确认数据时的日期（跨午夜请求按此规则精确切分）。
  - 输出速率：已确认输出 token ÷ 首输出后经过时间的平均值（tok/s），流结束后冻结；不足 50ms 或无输出 token 时显示“—”。
- **管理接口与推送**：
  - `GET /api/dashboard`：返回版本信息、启动用量、今日与累计汇总、最近三条请求、进行中列表及年度热力图。请求摘要携带账号 ID，最近请求和进行中列表结合账号列表显示别名或昵称。
  - `GET /api/dashboard/events`：SSE 增量实时推送，建立连接时发送完整快照，后续最多每秒 4 次合并推送，提供 15 秒心跳。断线重连重新获取完整状态，通过版本号避免旧数据覆盖。离开页面自动断开。
  - 仪表盘快照先复制服务状态，再在服务锁之外读取每个进行中请求，避免与请求用量更新互相等待。前端首屏请求 10 秒超时；若 SSE 已返回快照，即使普通首屏请求尚未结束也直接退出 loading。
- **实时请求浮窗**：桌面壳提供独立小窗（`--hud-window`）展示最多三条请求的账号、模型、已确认输出速度、状态和耗时，并始终显示今日 Token 与请求次数；空闲时明确显示当前空闲。小窗通过标题区域拖动，不依赖主窗口，主窗口关闭后仍可继续保留；直接关闭小窗会同步关闭服务端开关。托盘右键菜单提供“打开浮窗／关闭浮窗”开关，仪表盘继续使用应用级快照与 SSE；数据口径一致，上游未提供 token 时显示“—”，不做估算。浮窗使用深色背景、今日输入输出统计和紧凑请求列表，宽度不足 300px 时隐藏账号名；独立小窗铺满原生窗口；去除原生边框后重新计算客户区并同步 WebView 尺寸。340×240 浏览器预览已使用真实请求验证，桌面壳最终外观和拖动手感仍需重启后人工复核。
- **已知限制**：
  - 第一版不包含全量请求历史查询页，仅展示最近三条请求及超过三条时的进行中展开列表。
  - 依赖上游模型接口返回的真实 token 数据，若上游仅在流结束时返回 usage，则本次启动和今日用量在流结束时更新。

config.json 保留底层基础配置接口，当前页面不提供配置表单；runtime.json 保存临时地址、进程号和管理令牌（不要分享该文件），正常退出会删除；运行日志按本地日期写入 `logs` 目录下的 `client-YYYY-MM-DD.log`，跨天自动换新文件，同一天多次启动继续追加，记录启动错误、窗口回退浏览器和 WorkBuddy 11128 请求结构诊断；logs 目录跟随 `--data-dir`，旧版数据目录下的 `client.log` 已不再写入。webview 目录保存窗口浏览器数据。账号元数据保存在 accounts/accounts.json，上游凭据经 Windows DPAPI 保护后存放在 accounts/keys 下。

## 小涛 Agent

Agent 输入框粘贴时，如果整段内容被 ` ```markdown ` 或 ` ```md ` 围栏包裹，会去掉最外层围栏并按 Markdown 格式插入；其中的代码块仍会保留。带代码样式 HTML 的粘贴按纯文本插入，使用硬换行保留行结构；在代码块内的粘贴沿用原有行为。可在 `frontend` 运行 `node --test tests/markdown-paste.browser.test.mjs` 验证，默认使用 `/usr/bin/chromium`，也可通过 `XIAOTAO_TEST_BROWSER_PATH` 指定浏览器。

聊天消息按 Markdown 展示，支持段落、列表、链接、表格和代码块；长代码可横向滚动。
执行过程按时间显示在所属对话中，每段过程可以单独展开或收起。
过程面板位于助手头像旁，默认折叠并显示最近一步及耗时，步骤结束后继续保留最近一步，直到有新步骤；点击可按顺序查看完整步骤，结束后自动收起并直接显示回复。向上查看历史时不会被新步骤强制拉回底部。
展开的过程列表浮在对话上方，不改变页面高度；列表有最大高度，可在面板内滚动查看。
浮层展开和收起有短暂过渡，并遵循系统减少动态效果设置。
步骤列表以紧凑单行展示，过长的详情可悬停查看；不足一秒的耗时按毫秒显示。

常用模型的 ID 和显示名称保存在当前客户端的本地浏览器存储中，重新进入时直接使用缓存；只有打开 Agent 设置才加载完整模型目录。目录加载失败或暂时缺少某个已选模型时保留原选择，实际调用仍取决于账号和模型是否可用。

侧边栏标题显示当前视图，点击右侧切换图标可选择“按项目查看”或“按会话查看”，选择会自动保存。侧边栏支持“项目”和“会话”视图：项目视图按目录分组，未选择项目的会话放在底部“最新”；会话视图按最近更新时间排序。会话可经确认后删除，消息和执行记录同时删除；运行中的任务须先停止。删除会话、移除账号和重新生成 API 密钥共用随主题切换的确认弹窗，支持键盘操作和 Escape 取消。旧版 JSON 迁移备份仍保留。
项目视图中点击项目名或“最新”可展开、收起对应会话列表，默认展开。

Agent 页首屏为简洁的聊天空状态；发送第一条消息时创建会话，输入区使用 Tiptap。普通段落按 Enter 发送、Shift + Enter 硬换行、Ctrl/⌘ + Enter 强制发送；列表内按 Enter 或 Shift + Enter 新建下一项，空项再回车会退出当前层级；标题、引用和代码块内优先保留编辑行为，代码块按编辑器规则换行和退出。发送内容按 Markdown 序列化，列表、标题、引用、粗体、斜体、删除线、链接、行内代码、代码块和分割线不会在发送时丢失结构。行内代码支持先输入一对反引号、再填写内容，光标移到末尾按空格后转换样式。输入框外左上角管理项目：项目弹窗通过系统文件夹选择目录，并可设置项目显示名；项目显示名随会话保存。桌面窗口使用 Windows `IFileOpenDialog` 只选目录，并通过原生窗口事件异步回填；本次修复后桌面交互仍待验收。输入框右下角只保留 Agent 设置中勾选的常用模型；Agent 设置弹窗按来源列出完整聚合目录、支持搜索与批量勾选，选择保存在本机浏览器存储中。浏览器入口无法获取本机文件夹路径，请在桌面客户端选择项目。任务优先使用已启用账号中聚合出的完整模型 ID，不默认伪造可用模型。没有模型时页面会引导到“账号与配额”。

首版支持：

- 单会话读写项目文件、字面搜索和运行非交互式命令；Windows 下后台 PowerShell 不弹出控制台窗口，输出仍显示在执行过程中。

执行过程与紧接着的助手回复共用一个头像：头像定位到内容列左侧的独立留白中，执行卡片、回复正文与输入框左边缘对齐，不再重复显示头像；没有前置执行过程的独立回复仍显示头像。验收检查有工具与纯文字两种回复，以及窄窗口下的正文对齐。

Agent 消息区与输入框共用 --agent-content-width / --agent-content-edge 布局值；窄窗口同样保留头像留白，避免偏移头像被滚动区域裁剪。

## 会话与历史性能（2026-11-03）

侧边栏采用虚拟滚动，只挂载可见范围及上下约 280px 的预留行；项目折叠后内部会话不挂载。排序与分组缓存，输入和任务秒级计时不会重建侧边栏。支持方向键、Home / End 导航，切换会话时将选中项滚入可见范围；菜单打开或行仍有焦点时保留对应节点。

正文缓存历史消息与 Markdown 渲染。打开会话先取最近一批消息及执行记录，向上接近顶部时自动加载，也可点击“加载更早的消息”；失败后显示重试入口。加载、重试和追加旧历史时保持阅读位置，切换会话后显示最近内容；发送新消息保留已加载历史。分页只影响界面，模型继续从 SQLite 获取完整上下文。

每批最多 80 条消息/活动，记录 JSON 内容合计软上限 256 KiB；单条超长记录完整返回，不截断。批次可能落在某轮执行过程中，继续向上加载后会按时间合并。聊天正文目前没有动态高度虚拟化，持续翻阅仍会累积节点；会话摘要也暂未分页。

在 `frontend` 执行 `npm ci` 后，可运行 `npm run test:history`，测试自动启动独立 Vite，并拦截全部 API 请求使用合成测试数据，不访问运行实例。默认使用本机 Edge 无头模式；可设置 `XIAOTAO_TEST_BROWSER=chromium` 并先运行 `npx playwright install chromium`。已覆盖 1 万条合成会话的节点范围、折叠、键盘、菜单、历史加载失败重试、滚动位置、发送保留历史及切换会话后的旧响应隔离。该结果不代表真实 WebView2 桌面压力验收。
