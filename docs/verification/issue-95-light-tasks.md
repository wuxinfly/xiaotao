# #95 轻任务直通与 Task 升级验收样例

本参考用于单会话小改动直通与持久 Task 升级的人工对照与行为验证。

## 场景对照表

| 场景 | 旧式工作流（默认委派与 Task） | 轻任务直通工作流 | 生成文件数与状态对比 | 正确性与安全检查 |
| --- | --- | --- | ---: | --- |
| **小范围单会话改动**（如修复拼写、修改单行配置、单一小函数调优） | 创建 Task → 委派 Worker → 写入 spec/snapshot → 产出 Handoff → 压缩收尾与经验审查 → 归档 | 小涛在当前会话内直接完成检查、修改与必要测试，交付简短结果 | 从生成 5+ 个 `.xiaotao/` 状态文件降为 **0 个** | 修改在明确授权范围内，完成必要验证，不留状态碎片 |
| **跨会话持久任务**（如大型重构、跨模块功能迁移、需多次交互的任务） | 创建正式 Task，记录目标与执行上下文 | 识别出跨会话与断点恢复需求，直接建立正式 Task 并按需委派 Worker | 完整保留 Task、快照、上下文与 checkpoint | 保证新会话中可精确定位并可靠恢复进度 |
| **直通任务中途变复杂**（如小改动中途发现连锁依赖或架构缺陷） | 一开始即进入重量级 Task 流程 | 直通启动，发现变复杂后先固化已完成改动、验证与来源，再平滑升级为 Task | 无缝衔接并落盘 Task 元数据，避免会话记忆丢失 | 已完成工作不被重复执行，未结工作在 Task 中继续 |
| **一次性任务确需隔离或缺失能力**（如需要宿主只读工具隔离的日志分析） | 所有技术工作一律委派 | 仅在确需工具隔离、补充小涛缺失能力或用户明确要求时使用 ephemeral Session Worker | 不创建持久 Task、快照或 Handoff | 普通轻任务不会仅因子代理可用而被委派；Session Worker 不宣称可跨会话恢复 |
| **高风险/破坏性操作**（如部署、分支 push、删除文件、权限凭据变更） | 必须在执行前请求明确授权 | 无论直通还是 Task，**同等严格执行立即询问与明确授权** | 0 个不当特权文件 | 直通绝不绕过授权边界与破坏性保护 |
| **显式记忆请求**（用户明确说“记住这条规范/配置”） | 触发 Memory Worker 完整提炼与审计 | 沿用现有 `explicit-create` 快速路径（有界读取 ≤ 3 条并保存） | 仅按记忆协议写入必要条目 | 不强行创建业务 Task，也不吞没用户偏好 |

## 指标量化期望

- **生成管理文件**：小改动从 5~8 个 `.xiaotao/` 文件（task.yaml, spec.yaml, handoff, completion 等）减少至 **0**。
- **操作步骤/交互轮次**：单会话任务省去委派包组装、快照持久化、Handoff 校验与收尾等待，步骤数减少 50%+。
- **上下文开销**：无需加载 Worker 隔离协议与多层状态，显著降低模型上下文占用。
- **安全性与可靠性**：授权范围与必要验证 100% 保持一致；复杂与跨会话任务 100% 可恢复。
