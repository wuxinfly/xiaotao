# 首页办公室协作验收

## 操作路径

1. 在首页选择项目，从左下「办公室」打开右侧工作区。点击员工后在右侧打开对话。收起员工标签再从办公室或「员工动态」重开，确认仍能看到原有对话。
2. 在主输入框选择 `@员工`，发送明确的任务。确认主会话保持选中，消息卡和状态菜单显示真实员工进度。通过卡片打开右侧对话，确认可查看过程和工具审批。
3. 员工提问时，从原卡片或右侧对话直接回复。另起一轮点「让小涛回复」，验证依据不足时继续等待用户。查看右下提醒，确认输入焦点没有被抢走。
4. 完成一个包含项目约定的员工轮次，关闭主会话后重开。确认同一员工能利用已提炼约定，旧临时对话无法回读。用第二项目的同名角色验证隔离。模拟总结失败，确认输入框上方提供重试、下一轮仍可发送、较早的约定仍可补存，以及关闭主会话前会确认是否放弃。检查员工消息和执行过程使用员工头像。
5. 验证普通切换和刷新保留临时对话。确认关闭或删除主会话只清理其关联数据，项目文件和其他主会话独立。
6. 主会话模型从目录移除后，让使用可用模型的员工分别回复寒暄和项目约定。确认寒暄跳过总结，项目约定仍能保存。模拟摘要格式错误，确认可看到原因。准备多轮未保存记录，确认点一次重试可以依次补存。
7. 在员工对话用主会话同样的模型菜单和发送按钮发送。确认发送后出现员工头像和「正在思考」气泡，模型开始输出后切换到流式回复和执行统计。
8. 在新建和已经出现过错误自称的员工对话里询问身份，确认提示使用当前员工名称与职责。分别检查小涛主会话、无工具的员工闲聊和有审批的员工任务。
9. 用可暂停的流式模型响应测试员工对话。暂停在首段后确认该段已显示，恢复后确认后续分片追加、最终气泡展开。重复同一分片时文字只出现一次，断线后可从最新历史补齐。
10. 使用支持图片的模型，在员工对话粘贴截图或用「添加图片」选图，验证预览、移除、纯图片发送和历史回显。对员工任务的待回复问题发送带图消息，验证有序送达。不支持图片的模型显示提示。
11. 创建员工并确认任务工具默认跟随小涛。编辑后仅打开读取，派任务确认能读文件，修改、命令和 MCP 不可调用。关闭最后一个权限后继续任务，确认下一轮无工具。恢复跟随后核对审批仍由小涛当前访问模式决定。检查任一配置下员工闲聊始终无工具。

## 自动验证入口

- 前端目录执行 `node --test tests/home-office-collaboration.browser.test.mjs tests/office-entry.browser.test.mjs tests/office-member-execution.browser.test.mjs tests/office-team-real.browser.test.mjs tests/office.browser.test.mjs tests/navigation-layout.browser.test.mjs`。
- 客户端目录执行 `go test ./...`、`go vet ./...`、`node tools/check-go-size.mjs` 和 `./build.ps1 -Env uat -Verify`。前端 lint、size 和 build 也可在前端目录独立执行。

浏览器用例覆盖交互和隔离 Go 服务中的办公室入口及团队数据，模型协调、记忆和派单走可重复的本地模型替身。真实配置模型的文本质量和原生 WebView2 操作需要单独验收。

本次结果：9 项浏览器回归通过，Go 全量测试、vet、前后端尺寸检查、前端构建和 UAT 验证包构建通过。
