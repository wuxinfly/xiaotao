# #97 用户可见回复验收样例

以下样例用于同一长任务和新会话恢复的人工对照。内部 Task、checkpoint、Detailed Result 与 Handoff 仍须完整保存；计数只针对用户可见中文字符，不用三句上限截断关键信息。

| 场景 | 旧式用户回复示意（字） | 简短回复示意（字） | 正确性检查 |
| --- | ---: | ---: | --- |
| 长任务发现问题 | 逐条罗列检索、读文件和 Worker 步骤（约 150） | “发现登录回调有重复请求，正在修复。完成后跑相关测试。”（约 27） | Task 记录包含具体证据与修改位置 |
| 长任务完成 | 复述全部实施过程及内部路径（约 180） | “登录回调已修好，相关测试通过。还有跨浏览器验证未做。”（约 29） | 不隐瞒剩余验证与关键风险 |
| 新会话有活动 Task 和 checkpoint | 复述完整项目背景与所有历史（约 220） | “上次已改完登录流程，还差两项测试。我继续验证。”（约 24） | 唯一匹配当前任务、下一步在授权内 |
| 新会话有两个可能任务 | 选最近任务或展开两份历史（约 180） | “有登录和支付两项未完工作，你想继续哪一项？”（约 23） | 不猜目标，等待用户决定 |
| 用户要求详细依据 | 仍只给一句结论（约 25） | 按需给出改动、测试结果和可核实的证据路径 | 证据与内部记录一致 |
| 恢复快照缺失 | 声称无项目记忆（约 10） | “当前无法取得项目状态概览；我先检查现有工作记录。”（约 27） | 不把读取失败误报为无任务 |

验收时记录同一任务在规则调整前后的实际用户可见字数，并核对活动 Task、checkpoint 与 Handoff 内容完整；若宿主没有可运行的会话样本，标记为待实测，不把这些示意字数当成实测结果。
