# 办公室工作台改版

后续工位、角色动作与日夜场景见 [办公室工位、角色动作和日夜](2026-11-14-office-workstations.md)。
抽屉、对话复用、资料预览与走路动作细化见 [办公室交互细化](2026-11-14-office-interaction-polish.md)。

本次替换 [团队与 3D 第一阶段](2026-11-13-agent-office-team-3d-design.md) 的强制进场引导和旧场景视觉。用户反馈：左下入口偏出窗口，部分项目切换后只剩二维列表，场景模型和任务操作难用。

左下导航固定在 Agent 侧栏的布局底部，会话区独立滚动。打开办公室后，当前项目的 3D 房间、任务快照和组队设置各自加载。首次进入可主动点击「组建小队」，关闭弹窗仍可回来继续，点「稍后设置」则保存跳过状态。即使项目只有内置的小涛，仍显示房间和服务返回的真实成员。切换项目会清空旧任务、对话选择和任务筛选；不会把上一项目的数据展示在新项目里。

场景使用本地 GLB，包含海底观景窗、工位、休息区、资料架以及四种可配色的机器人外观。镜头自适应取景，可平移、缩放及复位。点击小涛或团队角色打开对话，点击正在执行任务的成员打开任务详情；点资料架或「资料馆」查看产物。工位跟随成员扩展；完整团队和键盘入口也可从右侧抽屉的「团队」标签打开。图形或模型资源出错时用二维列表替代场景。

浏览器验收：在 `xt-client/frontend` 执行 `node --test --test-concurrency=1 tests/navigation-layout.browser.test.mjs tests/office-entry.browser.test.mjs tests/office.browser.test.mjs tests/office-team-real.browser.test.mjs`。覆盖侧栏边界、未建队和跳过后的 3D、项目切换和快照隔离、加载失败后重试、窄窗口、角色持久化、任务和资料交互。真实服务测试使用隔离 Go 数据目录和 Vite 代理，不调用真实模型。浏览器验收不能代替 Windows WebView2 壳验收。
