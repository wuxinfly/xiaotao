# Agent 对话引用设计

日期：2026-11-04。

状态：首版已实现。模型摘要、完整 WebView2 实测和引用标签的键盘删除仍待后续；首版按已确认行为不做原地更新或版本链。

## 目标

在 Agent 输入框输入 `@` 引用其他对话，让当前对话快速借用已有背景、结论和待办，减少人工复制。首版只引用对话内容，不带入来源项目的文件、工具原始输出或运行环境。

## 已确认行为

- 默认搜索当前项目，可切换搜索所有项目；支持标题搜索、方向键选择、Enter 确认和 Escape 关闭。
- 一条消息可引用多个对话，同一对话只添加一次；中文输入法选字期间不抢回车，代码块中的 `@` 不触发选择器。
- 引用固定在发送时的内容。来源后来更新时显示“有新内容”，用户重新引用最新版本；不原地改写旧消息的依据。
- 摘要作为内部参考，直接回答当前问题；只有用户要求汇总时才展示摘要。
- 摘要不足时自动读取直接引用对话的相关原文，并显示正在查看的来源和进度。不递归展开来源对话里的引用。
- 只读取直接引用对话中用户和助手的文字回复。工具步骤可保留标题、时间和结果状态作为背景，原始命令输出、文件内容和工具参数不进入引用上下文。
- 内容冲突且有明确变更说明时采用新结论，否则指出冲突并询问用户。
- 引用内容固定后，来源被删除仍可查看已保存摘要，但需要明确提示原文不可用。
- 正式版与 UAT 的会话搜索、引用快照、摘要和读取缓存继续隔离。

## 方案选择

首版采用“输入引用标签 + 发送时冻结快照 + 后端上下文组装”。

不选直接拼接完整原文：实现简单，但难以控制上下文，长日志和代码会让后续轮次迅速膨胀。

不选原地更新引用：来源变化会悄悄改变旧消息的依据，还需要维护版本链和缓存失效规则，首版复杂度不值得。

接口兼容：现有 `/messages` 调用不带 `references` 时保持原发送行为。引用字段、快照表和查询工具单独增加，不改已有会话和工具调用数据的含义。上下文组装先接入引用消息，再逐步覆盖普通历史裁剪，避免一次性重写运行内核。

## 输入与消息模型

Tiptap 增加对话引用 inline node。标签展示对话标题；节点属性保存当前环境内的会话 ID 和显示信息，但不以 `@标题` 文本作为业务身份。发送时从编辑器文档提取正文和去重后的引用列表，正文中保留可读标签。

输入框草稿与发送正文分开保存：正文用于展示和恢复草稿，引用另存为结构化列表。粘贴纯文本 `@标题` 只当普通文字，不自动转成引用，避免伪造来源身份。

发送接口从仅接收 `content/model` 扩展为同时接收引用列表。前端提交引用 ID，后端在一个事务中读取来源元数据、确认来源属于当前环境并确定冻结边界，返回引用快照 ID。不能在服务端重新解析正文里的 `@`。

引用快照保存来源会话 ID、标题、发送时的最后可见位置、摘要有无、摘要文本或缓存键及创建时间。展示用的用户消息保存原始正文和引用列表；后端另行保存本条消息的模型带入内容，避免展示内容与模型上下文互相污染。

首版限制一条消息最多引用 5 个对话，单个来源带入上限 64 KiB 文本，所有来源合计 128 KiB；达到上限时截断并标记，不接收无限增长的单条记录。

引用关系、快照和摘要缓存使用独立表，以引用 ID、来源会话 ID 和冻结位置建立索引。普通消息仍按现有 `(session_id, position)` 保存，删除来源会话不级联删除已保存摘要。

每轮实际发给模型的引用内容有硬上限，不随历史轮数同步增长。旧轮次的引用只保留压缩概况；详细原文在被读取后缩成带位置的摘要记录。工具调用与结果仍保持配对，不能因裁剪拆掉调用链。

## 上下文组装

新增独立的模型上下文组装步骤，输入完整会话和本轮引用快照，输出用于模型请求的消息。展示历史继续完整保存；组装时按顺序保留系统提示、项目指令、当前用户要求和必要的工具配对，再在预算内加入引用。

首版建议上限：所有引用概况约 2,000 tokens；单次原文读取最多约 1,000 tokens；每轮新增原文合计最多约 3,000 tokens。预算是上限而非目标值，总上下文不足时继续收紧。多个引用先保证每个都有简短概况，再按与当前问题的相关性分配剩余空间。首版先执行 64 KiB / 128 KiB 字符上限和确定性摘要；token 估算与动态预算尚未接入，不能把字符上限当成已完成的 token 预算能力。

摘要保留关键背景、已确认结论、待办、分歧和对应消息位置。不默认包含完整代码、长日志和重复讨论。首版直接对冻结文字做确定性截取，不额外调用模型；后续如改模型摘要，同一快照缓存复用，超长来源分段整理，不把整段原文塞入当前对话。

读取原文使用专用只读工具，只接受当前用户消息直接引用的快照和版本范围。先搜索相关消息，再读取相邻片段；结果带来源位置并去重。达到预算时明确告知模型内容不完整，不能把“没读到”当成“没有”。

来源内容一律作为参考材料。其中的旧指令不能覆盖当前用户要求，也不能改变当前项目工作目录或工具权限。

## 失败与异常

- 摘要生成失败时提供重试，不静默回退成完整原文。
- 引用来源不可用、已删除或权限不匹配时，不创建新快照；清楚提示哪条引用失败。
- 来源仍在回复时，只冻结发送瞬间已保存的内容，并提示来源尚未完成。
- 来源会话仍在写入时，快照与来源列表读取使用一致性读事务；不能出现消息已列在来源里、但冻结位置看不到的半提交状态。
- 来源有新内容时显示轻量提示和重新引用入口；旧消息仍使用旧快照。
- 达到单条或总量上限时显示已截断，模型需要更多内容应请求用户补充引用。
- 引用、搜索和摘要操作必须有加载、成功、失败及减少动态效果状态。

## 前端交互

`@` 选择器挂到 body，不能依赖页面容器的 `position: fixed` 包含块。默认显示最近对话，支持项目筛选和标题搜索；显示项目名与更新时间。选中后插入可删除标签，支持键盘移除和焦点恢复。

消息中的引用标签可以打开摘要和来源信息，并提供跳转原对话入口。来源更新提示靠近引用标签，不占用输入区布局高度。引用生成和原文读取都复用现有过程面板，显示来源标题和真实状态。

## 验收

Go 覆盖：发送接口引用校验、快照边界冻结、同源会话范围、直接引用不递归、文字过滤、工具配对保留、摘要失败、来源删除、预算截断、去重与游标稳定性；正式版与 UAT 路径隔离。

前端覆盖：`@` 搜索与项目切换、多个引用、去重、删除、中文输入法、代码块不触发、键盘导航、浮层定位、失败重试、来源更新提示、减少动态效果，以及窄窗口和 WebView2 入口。

上下文回归：连续多轮引用后，旧原文不会每轮完整重发；当前问题相关片段优先；摘要和原文均不超过预算；引用查找不会越界到间接引用。
