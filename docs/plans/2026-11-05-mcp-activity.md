# MCP 执行过程可读性

## 问题与设计

真实浏览器调用已由用户截图确认可运行，但执行过程只显示“调用工具”。当前 activity 使用 mcp_N 临时别名，未保存真实服务与工具标识。

将服务名、原始工具名和有限长度的参数/结果预览保存进活动记录。常见 Chrome 工具使用明确中文动作，未知工具显示原始名称；摘要仅展示 URL、页面或元素标识等目标，不把输入文本当成标题。参数和结果使用默认收起的原生 details，保留键盘操作。历史记录不推测编号对应工具。

## 实施与验证

1. MCP 连接保留服务名；生成活动时使用真实工具名，运行和完成事件使用同一活动信息，结果预览截断。
2. 前端执行过程逐项展示名称和目标，并可展开查看服务/工具、参数与结果。字段可选，兼容旧历史。
3. Go 回归覆盖中文名称、未知回退、目标摘要、截断和事件/持久化；浏览器回归验证展开、长结果、失败、窄屏及旧历史。
4. 同步 README 和 Agent 架构；前端构建、Go 测试/vet 和规则检查。不覆盖正在运行的客户端。

## 验证与规则检查

- `npm run build`、`go test ./...`、`go vet ./...` 通过。
- `node --test tests/mcp-activity.browser.test.mjs tests/mcp-settings.browser.test.mjs` 通过；覆盖中文动作、真实工具标识、参数与结果、失败原因、旧字段兼容、390px 窄屏与主题；截图已检查。
- Go 测试通过真实协议子进程 fixture 验证运行/完成事件及保存后重新读取的活动元数据，工具回传 ID 保持原样。
- README 和 Agent 架构已同步，设置文案仍使用“添加 Chrome 浏览器工具”。旧记录缺少真实身份，不推测补全。
- 没有新增规则候选：这是当前功能展示缺失的修复，已有文档同步、交互反馈和验收约定可覆盖，不把单次文案要求提升为全局规则。
