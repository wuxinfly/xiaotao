# 多会话并行实现与验收

目标：同一客户端允许多个会话同时执行，共用用户选择的目录，不创建 worktree，不弹同项目并发提示。

设计已在本次对话确认：每会话独立运行、停止和接收事件；同项目运行任务作为不可信参考上下文提供给模型，不禁止同时修改文件。写文件检查读取后的变化，拒绝旧内容覆盖，模型重读合并，无法处理时告知用户。

实施顺序：
1. 前端按会话缓存运行事件，拆分导航加载和当前任务忙碌状态，保留草稿及滚动位置，侧栏标记运行状态。
2. 后端每轮模型请求刷新其他同项目任务摘要；明确共用目录和冲突处理指导。
3. 文件读写保存内容摘要并串行化工具写入检查，拒绝过期覆盖；命令及外部编辑不保证原子隔离。
4. 增加多会话并发及停止、文件过期重读、前端切换与后台事件回归；前端构建、Go test/vet、规则检查。
5. 同步 README、架构及验收结果。现有其他未提交修改保留，不提交或打包发布。

验收：A、B 同时运行，切换后事件各归其位；停止 B 不停止 A；运行时新建可用；草稿和滚动位置独立；同文件先后修改可继续，过期覆盖返回冲突且原内容保留。


验证记录：
- 隔离 SSE 浏览器回归通过：双会话同时运行、后台消息归属、独立停止、新建、草稿和滚动恢复、后台结束不清空新草稿、双确认排队。
- 既有引用和头像浏览器回归通过；前端 TypeScript/Vite 构建通过（保留现有大包提示）。
- go test ./... 通过；首轮桌面最小化交接测试偶发失败，单独重跑及全量重跑通过，未修改桌面实现。go vet ./... 通过。
- 规则检查通过。git diff --check 本次修改无空白问题；已有 VERSION 改动带 CRLF 提示，保留原有版本修改。
- README、Agent 架构、客户端概览已同步。规则候选 agent-shared-directory-concurrency 记录两次用户纠正，待审阅，未自动应用。
- 未打包或替换运行中的 EXE；桌面 WebView2、真实账号并发与限流仍待新包人工验收。
