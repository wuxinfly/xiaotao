# 项目 Agent 办公室：阶段一实现

日期：2026-11-12。

状态：阶段一最小闭环已实现（单项目、单执行者、真实状态与记录）。多执行者自由交流、完整工作流编辑器、团队统计和知识库仍未实现，文中「未实现」项不代表已有能力。产品方向见[办公室设计草案](2026-11-12-agent-office-design.md)，交互原型仅作布局参考，其中数据均为演示数据。

## 目标与范围

一个项目目录对应一间办公室。用户在办公室给小涛一个任务，小涛安排一个执行者在项目里真实执行；办公室和任务视图展示同一份真实运行数据，包含状态、执行过程、交流记录和可识别产物。

本次只做：

- 项目内发起任务，指派单个执行者；
- 区分排队中、进行中、等待确认、已完成、失败、已取消；
- 查看执行过程和交流记录；
- 用户消息排队，本轮成功结束后送达；
- 从写入活动识别产物，记录来源并保留在项目资料架；
- 状态、记录和产物按项目目录归属，不跨项目展示。

## 现有基础与缺口

- Skill 的 Worker 委派协议是语义约定，客户端并没有独立子 Agent 调度；两者不是一回事。
- 客户端已有会话、工具活动、取消和并行会话，但一次只能执行一轮，运行中再发消息会被拒绝（`小涛还在处理上一条消息`）。
- 审批只在执行流里出现，没有列表接口；重启后审批丢失。
- 没有任务、产物、消息队列的持久模型，也没有项目级视图。
- 同项目会话共用工作目录；文件工具靠读取摘要检查冲突，命令和外部编辑不参与，不能称为隔离。

## 数据与归属

新增 `internal/office`，使用独立数据库 `data/office/office.db`（WAL、单连接），不向 `agent.db` 加表：

- `office_tasks`：任务本身，含项目路径、标题、目标、状态、执行者、会话 ID、运行 ID、统计、等待原因、审批信息、时间。
- `office_messages`：用户消息及投递状态（排队/已送达/失败）。
- `office_artifacts`：产物记录，主键为 `(task_id, path)`，含任务、项目、工具、运行和活动 ID、大小和摘要。

项目键沿用客户端现有规则：路径小写、清理并统一斜杠。所有查询都按项目键过滤，任务详情、产物和消息都校验所属项目；跨项目访问返回 404。

任务与执行者是一对一：创建任务时同步创建一个 `Role=executor` 的 Agent 会话，执行者会话不出现在小涛的普通会话列表、对话引用候选或项目列表里（项目仍需用户自己保存）。任务执行走现有内核，不新增第二套模型调用或工具循环。

## 执行与状态

- 创建任务后立即在独立 goroutine 中执行，使用办公室自己的可取消 context，不绑定 HTTP 请求；离开页面不会取消任务。
- 任务状态：`queued`（刚创建）、`running`、`waiting`（等待审批）、`completed`、`failed`、`canceled`。内核没有 waiting，等待只由真实审批事件产生。
- 内核在真正开始前就失败（例如项目打不开、Core 准备失败）时，`RunTurn` 返回错误，办公室按失败记录，不依赖内核状态事件。
- 停止任务同时设置取消意图并调用内核取消；任务在运行结束时统一落为已取消。内核已经报告本轮完成时，晚到的取消不会把已完成改写成已取消。没有运行中的取消函数时直接标记取消。
- 服务启动时先调用一次内核 `ListSummaries()`，让内核登记会话并把上次残留的运行标为失败，再把办公室中所有未结束任务改为失败（原因：服务重启导致任务中断），排队消息标为未送达。**不自动恢复**：内核无法续跑半轮执行。

## 消息投递

运行中的执行者不能接收新消息，这是当前内核能力，不是办公室的取舍。实现方式：

- 执行中发送的消息先入库为「排队中」，任务详情可见，不显示为已送达。
- 一轮成功结束后，按创建顺序取一条排队消息作为下一轮继续执行；整条链路保持 `running`，不短暂显示完成。若消息恰好在上一条任务收尾时到达，会重新领取任务继续执行，不会卡在排队。
- 失败或取消后不自动补发，排队消息标为「未送达」并写明原因。
- 已结束任务再次发消息，会作为新一轮执行继续该会话。
- 「已送达」只在内核确认追加了用户消息（`session` 事件）后写入；没有该确认就保持排队或标记失败。

## 审批

执行者触发安全模式高危操作时，内核发出审批事件。办公室把任务标为 `waiting` 并展示工具和详情；用户允许或拒绝后调用内核 `ResolveApproval`，成功后任务回到运行。审批只存在内存里，重启即失效，因此重启后的任务直接标失败，不伪造「仍在等待」。完全访问模式下不会产生审批。

## 产物

- 只从 `write_file`、`str_replace` 的完成活动识别产物；命令或外部工具创建的文件不会自动出现，界面明确写出这一限制。
- 路径必须是项目根目录内的相对路径；绝对路径、`..` 和符号链接逃逸一律拒绝，避免把其他项目或主机文件挂到资料架。
- 记录工具、运行 ID、活动 ID、大小和 SHA-256，可在任务详情和项目资料架查看内容（UTF-8 文本，最多 256 KB，二进制不预览）。文件被移动或删除时明确提示，不保留过期副本。

## 统计与上下文用量

- 工具调用、读写文件、模型请求、时长来自真实运行事件；模型请求和输出 token 仅在内核有数据时显示。
- 输入/缓存 token 使用内核的 `inputKnown`/`cacheKnown` 标记；没有上游 usage 时明确写「上游未返回用量」，不显示 0 冒充真实值。
- 上下文 token 是本地估算，界面标注「估算」；团队统计本期不做，页面没有演示数字。

## API

均为同源管理接口：

- `GET /api/office/snapshot?projectPath=`：项目办公室快照（任务、成员、产物、能力边界、访问模式）。
- `POST /api/office/tasks`：创建任务并开始执行。
- `GET /api/office/tasks/{id}?projectPath=`：任务详情（含最近一页执行记录、产物、消息）。
- `GET /api/office/tasks/{id}/history?projectPath=&before=`：更早执行记录，沿用内核有界游标。
- `POST /api/office/tasks/{id}/cancel`、`POST .../messages`、`POST .../approval`。
- `GET /api/office/artifacts/{id}?projectPath=`：产物内容。

## 前端

新增左下「办公室」入口和独立页面，遵循现有导航、主题和弹窗体系：

- 办公室：工位只来自真实任务，执行结束的任务离开工位（任务记录和产物保留）；项目资料架显示识别到的产物。状态用文字和圆点同时表达，静止时也能读懂。
- 任务：列表和详情同屏，详情包含执行者、统计、用量、执行过程、产物、消息输入和审批按钮。
- 轮询用链式 `setTimeout`，仅在任务运行时快速刷新，空闲时放慢，页面隐藏时暂停，离开页面立即停止；不轮询未打开任务的完整历史，也不加载其他项目或其他任务的历史。
- 复用 `ModalFrame`、`ModalPresence`、确认框、Toast 和主题令牌；浮层挂到 body；尊重 `prefers-reduced-motion`，深海/浅海主题均有对应样式。

## 未实现与限制

- 运行中定向消息仍不支持，只做排队；失败或取消后不补发。
- 多执行者自由交流、临时工管理、团队统计、工作流编辑、项目知识库与记忆检索未实现。
- 产物只识别文件工具写入；命令、脚本和外部编辑无法自动归属。
- 同项目并发写入不是完整隔离：文件工具检查与写入串行，命令和外部编辑不参与，进程重启后观察摘要丢失。
- 服务重启后运行中任务标失败，不自动续跑；审批和排队消息同样不能恢复投递。
- 小涛仍是一个执行会话中的负责人角色，办公室的「安排」是创建一个执行者会话，不是独立子 Agent 运行时。
