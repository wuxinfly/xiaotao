# 小涛模型仪表盘实施计划

## 概要

实现真实代理数据驱动的仪表盘，以上传设计稿为视觉基准，依次展示本次启动用量、最近三条请求和年度用量热力图。

采用 **Go 内存统计 + SQLite 持久化 + SSE 页面推送**：请求明细保留最近 7 天，每日汇总长期保存。本次启动统计由服务内存维护，不通过页面轮询数据库。

## 一、数据存储与统计口径

- 新增独立的用量模块，使用 `modernc.org/sqlite`，不要求用户安装 SQLite，不引入 CGO 构建依赖。数据库位于数据目录下的 `data/usage.db`，跟随 `--data-dir`。
- 创建请求明细表：保存请求 ID、启动批次、模型、账号标识、开始/首输出/结束时间、状态、已确认的输入/输出/缓存 token，以及脱敏的错误摘要。不保存提示词、回复正文和凭据。
- 创建每日用量表：日期为唯一键，保存输入、输出、缓存命中 token，以及请求数和各终态数量；记录统计开始日期，以区分“没有历史记录”和“当天零用量”。
- 总 token 始终由输入加输出计算；缓存命中属于输入，不重复累加。未知指标用空值表示，不能自动记为零；汇总同时保留用量缺失情况，页面可提示统计不完整。
- 日界线固定采用 `Asia/Shanghai`。请求数归入开始日期，用量增量归入收到上游确认数据时的日期；跨午夜请求按这一规则处理。
- 同一请求的重复或累计用量事件只计算新增部分；请求明细与每日增量在同一个事务提交，终态只结算一次。
- 服务启动及运行期间每日清理一次：删除开始时间早于滚动 7 天、且已经结束的请求记录；不删除每日汇总。启动时将遗留的进行中记录标为中断，保留已确认用量。
- SQLite 使用 WAL、串行写入和有界批量提交。不上逐 token 写库；不执行日常全库压缩，允许复用已释放页面。

## 二、代理接入与实时状态

- 在现有代理入口统一记录请求生命周期，覆盖流式和非流式调用。通过鉴权并完成基本请求校验后创建记录；模型调用失败、取消及中断均保留状态。
- 在 Trae 上游事件解析处接入首输出和用量观察器，保留现有代理响应协议。首输出包括非空文本、推理内容或工具调用增量，不把连接建立和心跳算作首 token。
- 修正流读取错误与缺少正常结束标记的处理，避免断流被统计为成功。
- 统一规范上游用量字段，包括已有的输入、输出及可获得的缓存数据；不根据字符数、流分片数估算 token。
- 输出速率采用“已确认输出 token ÷ 首输出后经过时间”的平均值；完成后冻结。上游未提供可用 token 数据或时间不足时显示“—”，不承诺逐 token 的瞬时速度。
- 内存维护启动时间、启动批次、本次用量、今日/累计缓存以及所有进行中的请求。服务重启后本次用量归零，今日和累计从每日表恢复。
- 已确认用量及时进入持久化队列，提交成功后发布统计更新。存储故障不阻塞模型输出，但页面明确提示保存异常，不伪装成正常统计。
- 最近三条采用“进行中优先，同组按开始时间倒序”，仅在生命周期变化时重排；同时返回全部进行中的请求数量。

## 三、管理接口与前端页面

新增同源管理接口，沿用现有访问保护：

- `GET /api/dashboard`：返回版本号、启动信息、本次/今日/累计用量、最近三条请求、进行中数量、最近一年每日汇总及存储状态。
- `GET /api/dashboard/events`：SSE 订阅；连接建立时发送完整快照，之后发送合并更新，最高每秒四次，并提供心跳。断线重连重新获取完整状态，通过版本号避免旧数据覆盖新数据。
- 快照与请求生命周期共用内存状态时固定锁顺序：先复制服务状态并释放服务锁，再读取进行中请求锁。请求更新和结束不得与快照形成“服务锁等待请求锁、请求锁等待服务锁”的环。前端首屏请求设 10 秒超时，SSE 初始快照可独立结束 loading。

前端新增独立仪表盘功能模块：

- **用量概览**：本次总 token 最大，输入、输出、缓存为明细；今日用量次级，累计改为小字。数字使用等宽字体和千位分隔，首次加载不播放增长动画，后续更新平滑过渡。
- **请求列表**：状态与模型分别设列，等待时长只在耗时列展示；保留速度、首 token、输入、输出、缓存指标。支持失败详情展开，以及空状态、加载和连接中断反馈。
- **热力图**：自行实现 React + CSS Grid 组件，不引入大型图表库。展示截至今天的最近一年，七行对应周一至周日，月份按实际日期定位；范围外留空，未知历史与零用量区分。
- 热力图使用零用量加四档青蓝色，以正用量日期的分位数确定档位，处理重复阈值；悬停、聚焦或点击展示每日详情。今天有描边，窄窗口横向滚动至最近日期。
- 动效保持 120–220ms，支持快速反向操作与减少动态效果；键盘可操作请求展开及热力图详情。
- 第一版不新增完整请求历史页，因此不展示无去向的“查看全部”。超过三条进行中时提供可展开的进行中列表。
- 只订阅当前仪表盘所需的数据；离开页面关闭 SSE，重新进入重新获取快照。
- 增加独立桌面请求浮窗（`--hud-window`），显示最新进行中请求的账号、模型、速度和耗时，以及今日 Token 与请求次数；支持标题区域拖动、主窗口开关控制和直接关闭同步状态。主窗口关闭后浮窗可继续保留，仪表盘复用应用级快照和 SSE。

## 四、验证与验收

- **统计与存储**：验证累计事件去重、并发请求、事务失败、未知与零值、跨午夜、重启恢复、进行中转中断，以及 7 天清理后每日/累计数据保持不变。
- **代理链路**：使用可控上游验证流式和非流式、推理与工具调用首输出、正常完成、上游错误、取消、异常断流和缺失用量；确认观测逻辑不改变代理响应。
- **推送**：验证初始快照、更新合并、版本顺序、断线重连、慢消费者退出及订阅释放；确认页面刷新不触发高频数据库查询。
- **并发与启动**：并发快照与请求用量更新必须在超时内完成，不能因锁顺序反转死锁；同一数据目录的并发启动复用健康服务，单实例启动锁冲突不能误报为服务启动超时。
- **页面**：核对设计稿层级、数字动画、三条请求排序、七行日期布局、闰年、月份交界、空历史、浮层边界、缩窄窗口、键盘及减少动态效果。
- 在桌面壳和浏览器两种入口验收；真实 Trae 请求确认数据可获得程度，无法获得的指标保持“—”。
- 运行前端 `npm ci`、`npm run build`，客户端 `go test ./...`、`go vet ./...`、`./build.ps1`，以及根目录规则检查。检查新增 SQLite 依赖对构建和 EXE 体积的影响。

## 五、默认约定与文档

- 长期统计从功能启用当天开始，不追辞此前请求；累计表示每日汇总中所有已确认用量。
- 本次启动指本地服务生命周期，托盘隐藏、恢复及页面刷新均不重置。
- 最近 7 天是时间保留策略，不是固定条数或容量上限；不额外增加明细条数限制。
- 实时计数只使用上游确认数据；上游只在结束时返回用量时，主数字也在结束时更新。
- 更新客户端 README，说明数据库位置、保留策略、统计口径和已知限制；需要调整生成规则时编辑规则源并重新生成，避免手改 AGENTS.md。
- 实施时将本计划保存为 `docs/plans/2026-10-31-dashboard.md`；当前讨论阶段不修改项目文件。

- 2026-11-02 浮窗样式修复：独立入口补齐 box-sizing、深色底和铺满客户区的布局，隔离页面浮层的边距、外投影及窄屏双列规则；原生壳去边框后刷新客户区和 WebView 尺寸。已通过 340×260 真实 API 浏览器预览、前端构建与 Go 验证；桌面壳重启后的视觉及拖动验收待完成。
