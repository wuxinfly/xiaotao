# 办公室指定成员执行：第一阶段设计

日期：2026-11-14

状态：第一阶段已实现，自动验证结果见文末；真实模型与桌面验收待进行。

## 目标

让当前项目的指定成员真正执行任务，而不只是提供只读咨询。首阶段只打通一个成员的一个任务：

1. 用户与成员讨论需求。
2. 用户明确选择“交给TA执行”，确认任务目标、执行者和模型。
3. 该成员在自己的任务会话中使用现有 Agent 工具完成工作。
4. 用户在办公室查看实时过程、审批、取消和产物。
5. 任务结果回到成员沟通入口，用户可继续讨论或继续交代同一任务。

产品定义：**聊天是成员的沟通入口，任务是成员的工作实例，产物是任务的交付结果。**

## 本阶段不做

- 不做成员之间自动聊天、自动拆任务、自动交接或并行编排。
- 不做协调者自动选择成员，不根据职责文本自动授予权限。
- 不做新的模型循环、Worker 服务或第二套任务内核。
- 不做细粒度工具权限编辑器；能力标签仍不是权限声明。
- 不承诺操作系统级目录沙箱、跨项目记忆或服务重启后恢复半轮执行。
- 不改造现有首页任务，不迁移或删除旧的小涛执行者任务。

## 对话与执行方案

保留成员在项目中的持久只读对话。对话用于理解需求、讨论方案和展示关联任务，不能直接获得工具。

用户确认执行时，创建独立的执行任务会话。任务使用现有 `internal/agent` 内核及办公室单任务运行循环，获得与当前客户端访问模式一致的普通项目工具能力；安全模式继续要求高危操作审批。

执行任务会话记录稳定的成员 ID、创建时的身份快照及来源对话 ID。执行提示由服务端组合成员身份、职责、用户确认的任务目标和必要的讨论上下文；前端不能直接声明系统提示或权限。

讨论上下文默认携带当前对话中最近一组有界的用户与助手消息，并在确认面板显示将带入的摘要。任务目标及讨论总长度使用明确上限，超长时要求用户整理后再创建；首阶段不增加额外模型摘要请求。后续执行轮次只读取任务会话及已确认的补充消息，不持续同步之后的闲聊。

独立会话的理由：只读对话不应在用户未确认时改变权限；任务需要保留完整工具结果、审批和运行状态，不能只把讨论会话的 `ReadOnly` 标志改掉。

## 入口与信息架构

- 成员对话提供“交给TA执行”按钮；回复运行中不可创建，已有任务不影响继续只读讨论。
- 顶部“新建任务”保留，并增加必选执行成员。默认选择当前成员（若从聊天进入）或内置小涛，不自动选择其他角色。
- 确认面板显示任务标题、目标、实际执行成员、使用模型、讨论上下文范围和当前访问模式；模型默认取成员偏好，可按现有可用模型调整。
- 创建成功后打开该成员的任务详情，而不是显示“已交给小涛”。
- 成员对话展示关联任务卡片及真实状态，可进入任务。任务完成后展示结果摘要与产物入口，结果正文以执行会话的最终回复为准，不伪造一条成员已确认质量的聊天消息。
- 一个成员可以有多个历史任务；同一成员同一时刻只允许一个未结束任务。聊天与任务可分别运行，但移出成员时二者都纳入活动检查。

## 数据与身份

`office.db` 继续保存任务、消息、产物、对话关联和状态，不把运行记录移入角色 YAML。

任务增加：

- 稳定的 `memberId`，区分真正的成员任务与旧内置执行者任务。
- 来源 `chatSessionId` 及有界的讨论交接记录。
- 创建时的成员名称、职责和模型身份快照；角色后来改名、换模型或被移出，不改写历史任务。

执行会话通过结构化选项接收成员身份及职责，不能仅把任意角色文本拼进现有 `Role` 路由字段。普通 Agent 请求不能借该字段冒称办公室成员；身份由办公室服务从当前团队注册表验证后注入。

旧任务缺少 `memberId` 时保持旧行为，继续显示为“小涛执行者”，不猜测绑定到现有角色。

## 状态、消息与失败

- 沿用 `queued / running / waiting / completed / failed / canceled` 和单执行者事件循环。
- 成员状态来自该成员的对话及未结束任务，不能再用“角色任务尚未支持”为理由把所有执行显示成小涛分身。
- 任务执行中的补充消息仍排队，只在当前轮成功后送达；失败、取消或服务重启后不自动补发。
- 同一成员的后续任务必须等待前一任务结束；前端禁用与服务端冲突检查都要存在。
- 任务失败保留失败原因、已经产生的文件及历史；用户可显式继续交代，不能自动重试。
- 成员被移出或模型不可用时禁止新任务；已创建任务和历史仍可查看。运行中的成员不能被移出。

## 实时体验

首阶段让任务详情复用首页的 `RunTimeline`、消息及统计展示。办公室运行循环需要增加订阅者，只向当前项目、当前任务的已授权同源订阅转发真实事件；事件不携带密钥，断线重连后以持久历史补齐，不把事件订阅当作执行生命周期。

创建任务继续返回持久任务记录，前端另开事件流接收本轮消息、思考、工具活动和统计。将首页的事件解析、归并和运行条目生成提取成共享模块，避免复制 `AgentPage` 的大段状态代码。成员只读聊天可继续轮询；历史任务无需保持活跃事件订阅。

事件流只改善反馈速度，不改变排队消息、审批、取消和重启规则；断流不能伪装完成，也不能为了动画效果伪造进度、token 或工具状态。

## 安全与一致性

- 成员名称、职责、能力标签及历史对话都是提示上下文，不是访问控制配置。
- 成员任务使用现有项目工作目录、工具、MCP/Skills 和访问模式；界面明确其可修改项目文件。
- 所有创建、取消、审批及消息接口继续同源检查，并在服务端校验项目和成员关系。
- 创建任务必须先完成身份及模型校验，再持久化任务和启动执行；任一步失败不得留下永远排队却无执行者的任务。
- 3D 工位和人物状态只反映真实成员任务，不新增一个同名“小涛执行分身”冒充成员。

## 实施拆分

1. 扩展 Agent 会话的受信成员身份选项和提示组装，保留旧会话兼容。
2. 扩展任务请求、持久记录、成员执行校验、活动检查及快照视图。
3. 增加从成员对话创建任务的接口与确认面板；顶部新建任务支持选择执行成员。
4. 关联任务卡片、结果、产物及继续交代，复用首页任务过程组件。
5. 更新 3D 成员状态和团队移出规则，完成浏览器、Go、构建和桌面验收。

修改现有超限文件前先按客户端代码质量规则拆分；不得让 `AgentPage.tsx`、办公室服务或现有视图文件继续膨胀。

## 验收标准

### 核心闭环

- 与指定成员讨论后，经明确确认创建任务；实际会话身份、任务执行者和场景人物均为该成员。
- 成员能使用现有工具完成项目文件任务，最终回复、产物和任务状态真实可见。
- 从对话进入任务、返回对话、继续同一任务，项目和成员关联始终正确。
- 顶部新建任务可明确选择小涛或其他成员；未选择成员不能悄悄派给默认执行者。

### 隔离与权限

- 只读对话仍无工具，只有确认创建的独立任务具备执行能力。
- 非当前成员、跨项目成员、已移出成员及不可用模型不能创建任务。
- 职责和能力标签不会获得额外权限；安全模式审批、完全访问模式、取消和同源保护继续有效。
- 同一成员的并发任务返回冲突；不同项目的历史和运行记录不混淆。

### 失败与恢复

- 执行失败、取消、消息未送达及服务重启中断均有真实状态，不自动重试或伪造成功。
- 角色改名、修改模型或移出后，历史任务仍显示创建时身份。
- 快速切换项目、成员或任务时，旧请求不能覆盖新页面。

### 验证

- 为成员身份注入、任务归属、并发、权限、排队消息、重启和旧任务兼容添加 Go 测试。
- 为讨论交接、确认创建、过程展示、结果返回、窄窗口及减少动态效果添加浏览器测试。
- 运行客户端规定的 lint、size、前端构建、Go test/vet、Go size 和规则检查。
- 使用不递增版本的 `./build.ps1 -Env uat -Verify` 验证；真实模型和 WebView2 桌面验收单独记录，不以合成数据测试代替。

## 后续阶段

第二阶段定义少量可验证的成员能力模板和工具边界；第三阶段做用户确认的跨成员交接；最后才考虑协调者自动编排。每一阶段都应保持单任务内核、项目隔离和可追踪产物，不提前引入长期自治 Agent。

## 实施结果

- 成员对话与新建任务均可明确选择成员，服务端校验团队、模型、单成员串行和讨论归属。
- 独立执行会话保存受信成员身份，通用会话接口不能冒用；任务保存成员及讨论关联，旧任务保持旧归属。
- 任务事件、共享首页时间线、审批、取消、排队消息、产物和最近任务回聊入口已接通。
- 已覆盖 Go 成员派单、活动保护、项目隔离、事件退订及浏览器讨论派单和任务返回。
- 2026-11-14 自动验证通过：前端 `npm run lint`、`npm run check:size`、`npm run build`；6 条首页、办公室、成员执行、进入流程和导航浏览器回归；Go `node tools/check-go-size.mjs`、`go test ./...`、`go vet ./...`；规则检查和 OpenSpec strict 校验。
- `./build.ps1 -Env uat -Verify` 通过，生成 `dist/verify/xiaotao-uat.exe`，未递增版本，未覆盖正式产物。构建仅有既有大 chunk 提示。
