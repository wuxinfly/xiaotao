# Agent 历史列表优化实施计划

**目标：** 控制大量会话和长对话的首次加载、DOM 数量及重复渲染开销。

**架构：** 保留 SQLite 与模型侧完整上下文。侧边栏采用独立组件、缓存分组及固定行高窗口渲染；正文缓存 Markdown，并以双位置游标从 SQLite 分批读取消息及活动，向上加载时保持位置。正文动态高度虚拟化和会话摘要分页暂缓，待实测决定。

**技术栈：** React、TypeScript、Go、SQLite，无新增运行依赖。

## 实施步骤
1. 新增侧边栏组件，项目标题与展开会话铺平，窗口仅渲染可见项及预留项；支持键盘导航、活动会话定位及菜单。
2. 缓存排序、项目列表、消息时间线和 Markdown，隔离输入及秒级计时造成的重复工作。
3. 新增只读历史分页 API；消息与活动使用各自位置游标，合并为时间顺序页面，保留原完整详情 API 和模型读取逻辑。每页最多 80 条、内容软上限 256 KiB，单条记录不截断。
4. 前端使用分页 API，向上加载与手动重试，防止切换会话后的旧响应串入，保持滚动位置；发送后刷新已加载范围，不重置历史。
5. Go 回归验证分页边界、同时间记录、追加记录、内容上限与上下文完整性；运行前端构建、go test ./...、go vet ./...、规则检查。
6. 同步 README 与架构验收边界；说明未完成的真实桌面压力和交互验收，不用合成测试冒充真实实测。

## 实施结果

已完成步骤 1–4 与自动化回归；正文虚拟化和摘要分页按方案暂缓。侧边栏可见行定位进一步改为二分查找，滚动不扫描完整列表。新增 Playwright 仅为开发测试依赖，无新增生产依赖。

浏览器合成数据检查发现重试时错误提示移除会造成约 22px 位移，已将加载状态和错误变化纳入阅读位置补偿，并纳入回归。已覆盖 1 万条会话、折叠与键盘、菜单、历史重试与追加、发送和切换会话隔离；不是实际用户数据或桌面壳压力实测。README 与 Agent 架构文档已同步使用方式、接口和待验收边界。

规则检查：本次没有改变权限、构建方式或模块职责，没有新增可复用规则候选；滚动位置问题由代码回归覆盖。
