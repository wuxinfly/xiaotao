# 项目 Agent 办公室：产品设计草案

状态：讨论稿，阶段一最小闭环已实现。本文描述产品目标和后续设计；实际已实现范围、接口、验证结果与限制见[阶段一实现](2026-11-12-agent-office-implementation.md)。配套静态交互原型：[查看办公室原型](agent-office-prototype.html)，其中数据均为演示数据。

## 产品方向

一个工作空间对应一个项目，也是一间有记忆的 Agent 办公室。小涛是直接面向用户的负责人，负责理解任务、安排执行、协调和交付。用户可以选择工作流，也可以让小涛自主安排；办公室、任务和工作流视图从不同角度呈现同一次协作。

## 约定与体验

- 团队包括用户创建和小涛创建的 Agent，来源清晰可见；成员可以是全局配置或项目专属配置。全局成员跨项目复用身份、职责等配置，工作空间记忆不跨项目流转。全局成员是否需要先加入项目才能调用尚待决定。
- 临时工由小涛为任务安排，结束后退出办公室，记录和产物仍可追溯；用户可选择将其保存为团队成员。具体保存与审查交互待设计。
- Agent 接到任务时启动，围绕工作自主交流、查资料、交接产物；普通 Agent 向小涛申请帮手，由小涛安排。需要用户决定的需求取舍或权限问题由小涛带着具体问题提出。并发等资源范围可调整。
- 用户可直接与某个 Agent 对话；任务相关指令同步给小涛，必要时协调其他成员。实现时需明确消息投递、忙碌时的处理与同步失败的表现。
- 用户指定工作流时，关键步骤按设计执行；步骤内部可灵活安排，改变关键步骤前征得用户同意。未指定时，小涛自主安排，视图展示实际过程。关键步骤的标记方式和执行时修改规则待定。
- 工位呈现当前工作和正在使用的产物；重要产物放入项目资料架。产物可追溯创建者、任务、内容及使用关系；原始记录可查，不要求所有记录都变成可视化产物。
- 团队页区分创建来源、全局/项目范围和临时工，提供工作记录、调用次数与最近使用等统计。一次启动执行计为一次调用；失败、中断和完成分开显示。统计由真实运行记录计算，缺失时不虚构。

## 记忆与上下文

记忆全部留在所属工作空间：项目公共记忆供成员按需读取；Agent 的项目经历按 Agent 和工作空间隔离，第一次进入项目时个人经历为空；共享知识和经验也属于该工作空间，不设跨项目共享知识库。Agent 可以留下发现或候选经验；将经验提升为长期有效的项目约定前需确认，具体审核方式待定。

每次执行只加载任务、职责、必要规则和直接相关的简短进展；其他经验、交流及产物按需检索。经历引用任务和产物，避免重复存储全文；交接优先摘要加引用。长任务在上下文接近限制时保存目标、关键决定、进度和下一步，以支持恢复；原始记录可追溯。上下文占用仅在可可靠获得时展示，不能把估算当精确用量。

## 视图

1. **办公室**：工位、成员状态、工作中的产物和资料架；点击成员或产物查看详情。动画表现真实事件，静止时仍能理解状态。
2. **任务**：任务目标、进度、成员、产物及交接；可追溯等待和失败原因。
3. **工作流**：编辑可复用流程；运行时展示步骤状态。自主安排的任务展示实际过程，不假装执行了用户预设流程。
4. **团队**：管理成员与临时工，查看来源、范围、使用记录和统计。
5. **知识**：浏览工作空间里的记忆和经验，区分候选与已确认内容。

## 现有基础与缺口

- [小涛 Skill](../../xt-skills/xiaotao/SKILL.md) 已定义负责人、Worker 委派和任务交接；[协调协议](../../xt-skills/xiaotao/references/coordination.md) 支持根据宿主能力执行，不能把降级执行描述为独立 Agent。
- [项目记忆设计](../../xt-skills/xiaotao/references/memory.md) 已有索引、按需读取和经验审查思路，可作为项目内记忆的基础。现有 Skill 也有全局用户记忆，本方案要求新增 Agent 记忆限定在工作空间，具体接入边界需设计，不能假设现有全局记忆已经被隔离。
- 客户端已有会话、工具活动、取消及并行会话；但并行会话不等于多 Agent 调度。需要补充任务与执行者关联、消息投递、产物引用与状态事件等能力，才能驱动真实视图。
- 当前同项目会话共用工作目录，现有文件检查不能覆盖所有命令或外部编辑；重启后的运行中会话不会自动继续。多人并行写入和恢复必须单独设计与验证。

## 分阶段交付建议

- **阶段一：最小闭环**。一个项目工作空间中的任务由小涛安排一个执行者；显示真实状态、查看交流、生成并查看产物、保留任务记录。先核实底层是否支持运行中定向发消息；不支持时清楚提示，不能用假状态冒充。界面用办公室和任务视图呈现同一份数据。**已实现**：运行中不能定向送达，改为排队并在本轮成功结束后送达；等待状态只来自真实审批事件；产物只识别文件工具写入。详见[阶段一实现](2026-11-12-agent-office-implementation.md)。
- **阶段二：多人协作**。多个 Agent 的消息、交接和使用关系，临时工与团队管理，项目内记忆检索、可恢复执行及必要的资源限制。
- **阶段三：工作流**。可视化编辑和保存，指定任务运行，关键步骤变更的确认，以及运行过程展示。团队统计和知识管理可按实际基础分批加入。

这些是建议的交付切片，不表示后续阶段可以省略；每阶段需先验证真实运行、失败、取消、重启恢复和权限边界，再扩展视觉表现。

## 验收场景

- 用户选择项目、发起任务；办公室和任务视图一致地展示真实执行者及状态，失败、等待和完成可区分。
- 用户查看执行者对话和产物；运行中直接发消息仅在实际支持时可用，消息与负责人同步结果可见。
- 产物可打开并追溯创建者、所属任务、被使用关系；完成后仍能从资料架找到。
- 项目之间不自动共享记忆；新成员可按需读取项目公共记忆，不自动加载无关历史。
- 预设工作流的关键步骤改变前等待用户确认；自主任务展示真实执行过程。
- 原型中的演示数据不能作为实际状态或统计进入产品。

## 待讨论

全局成员加入项目的方式、经验提升为项目约定的审核流程、工作流关键步骤的定义、用户直接消息的投递语义、记忆删除和管理方式，以及执行资源的默认限制。
