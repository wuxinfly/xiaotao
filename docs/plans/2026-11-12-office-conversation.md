# 办公室成员对话

## 使用

选择项目后，点击场景里的成员，或从“成员”列表打开对话。每位员工在每个项目中有独立对话，可按需查看更早记录。聊天没有工具，无法读取项目文件或执行操作；员工只能根据对话中提供的信息讨论。等待回复时不能发送第二条，可以停止回复。中断的回复在重启后显示失败，历史仍保留。

成员对话在更宽的右侧抽屉中打开。输入区复用首页富文本编辑器，保留模型和上下文窗口，支持 Markdown 格式和发送快捷键。

需要执行时，使用成员对话的“交给TA执行”或办公室顶部的“新建任务”明确选择成员。确认后创建独立任务会话，成员对话不会自动获得工具。讨论交接和结果入口见 [指定成员执行设计](2026-11-14-office-member-execution-design.md)。

## 实现边界

`office.db` 按项目路径和员工 ID 关联会话；Agent 会话持久化无工具标记，运行时不提供工具、拒绝模型伪造的工具调用，也不自动启动 MCP。聊天会话不加载项目指令和技能；无工具并不等于操作系统沙箱。执行任务使用现有工具与权限模式，运行中的任务消息仍按既有规则排队。

## 验收

- 未组队时向内置小涛发送消息，检查回复及会话历史；在不同项目和成员间切换，确认记录互不混淆，刷新或重启后可恢复。
- 向员工发送想法，检查忙碌反馈、停止、失败与重新发送；服务端忙碌时返回冲突，不假装投递。
- 检查对话抽屉加宽、富文本编辑及发送后的 Markdown；执行按钮只有在成员对话就绪且没有未结束任务时可用，确认前不会修改项目。
- 深海、浅海和窄窗口检查场景、键盘焦点和减少动态效果；查看任务与资料架仍可用。
- 在项目中移动或删除已登记的文件后刷新办公室，确认资料架和任务详情隐藏对应项目，其他文件仍可预览。
- 自动检查包括无工具模式拒绝伪造写入、项目和员工会话隔离、停止和重启，以及浏览器合成 API 下的对话和富文本发送。真实模型、Windows 桌面壳和视觉效果仍需手动验收。
