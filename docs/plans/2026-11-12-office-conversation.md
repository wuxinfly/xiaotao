# 办公室对话与交接

## 使用

选择项目后点击办公室中的小涛、设计师或开发者，直接开始聊天。每位员工在每个项目中有独立对话，可按需查看更早记录。聊天没有工具，无法读取项目文件或执行操作；员工只能根据对话中提供的信息讨论。等待回复时不能发送第二条，可以停止回复。中断的回复在重启后显示失败，历史仍保留。

点击“整理交接”请当前员工基于对话整理内容；员工可能先追问。确认内容准备好后点击“查看交接并安排”，检查并按需修改内容，确认开始后才创建小涛的执行任务。这里传递的是当前对话的最后一条员工回复，不会自动传递完整历史。当前设计师和开发者只有独立聊天会话，执行仍由小涛的任务会话完成，员工之间也不能自动聊天或交接。

## 实现边界

`office.db` 按项目路径和员工 ID 关联会话；Agent 会话持久化无工具标记，运行时不提供工具、拒绝模型伪造的工具调用，也不自动启动 MCP。聊天会话不加载项目指令和技能；无工具并不等于操作系统沙箱。执行任务使用现有工具与权限模式，运行中的任务消息仍按既有规则排队。

## 验收

- 在两个项目和不同员工间切换，确认历史互不混淆；刷新和重启后可恢复对话。
- 向员工发送想法，检查忙碌反馈、停止、失败与重新发送；服务端忙碌时返回冲突，不假装投递。
- 请员工整理交接，确认弹窗中的内容与员工回复一致；取消不创建任务，确认后才开始执行。
- 深海、浅海和窄窗口检查场景、键盘焦点和减少动态效果；查看任务与资料架仍可用。
- 自动检查包括无工具模式拒绝伪造写入、项目和员工会话隔离、停止和重启，以及浏览器合成 API 下的对话和交接。真实模型、Windows 桌面壳和视觉效果仍需手动验收。
