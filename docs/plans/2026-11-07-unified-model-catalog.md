# 统一模型目录

用户确认：所有入口读取同一份目录；无数据时自动拉一次，之后仅手动刷新。Agent 设置刷新所有来源，账号页只刷新当前来源下各账号的数据。失败保留旧目录。

实现步骤：
1. 服务端按账号、来源和区域缓存目录，持久化到当前环境账号存储；取消五分钟过期和查看时强制刷新。不同账号权益不混用。
2. Trae、Antigravity 与其他动态来源共用读取、刷新、并发去重及失败保留逻辑。正常 token 轮换保留缓存，重新登录失效；删除账号清理目录。
3. 账号页区分读取与刷新；Agent 去除独立浏览器目录缓存，打开设置读取服务端，刷新按钮并行刷新所有启用账号，返回各账号失败提示。
4. 增加请求次数、并发、持久化、单账号刷新与全量刷新回归；构建前端，执行 Go 测试、vet 和规则检查，同步 README 与架构说明。

首次请求失败且没有可用目录时允许再次尝试。成功返回空目录也保存为已加载状态，避免每次查看重复请求。静态底表仅保留原有来源的降级语义，不冒充账号权益。

## 实施与验收

已实现上述行为。缓存包含公开模型信息与内部上游 ID/档位路由，内置降级目录继续明确标识为内置。旧 POST `/api/proxy/models` 全量刷新入口也更新统一缓存，GET 只读。

首次请求失败时的内置降级目录不是成功快照：后续读取每分钟最多自动重试一次，重启后可立即重试；成功目录仍不自动过期。

验证：前端 npm ci、npm run build、Go 全量测试、go vet、规则 check 均通过；浏览器目录与倍率两项回归通过。新增 Go 测试覆盖并发首次加载、无 TTL、重启持久化与内部路由恢复、普通 token 轮换/重新登录、成功空目录、单账号/全量刷新、错误保留与同源校验。浏览器使用隔离合成 API，验证全量与当前来源（含多账号）刷新、跨页面读取及失败保留。真实上游账号与 WebView2 桌面壳未实测，本次不发布安装包。
