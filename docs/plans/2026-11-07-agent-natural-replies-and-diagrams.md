# 小涛自然回答与图示支持实施方案

**目标：** 让小涛默认像同事一样清楚、自然地回答，并在有帮助时生成易读的图。

**方案：** 在现有 system prompt 中补充按需展开的回答和选图原则；客户端扩展 Markdown 渲染，将完整 Mermaid 代码块安全地转换成图。图来自同一次正式模型回复，不增加专门的模型请求；原始 Markdown 仍是会话持久化和复制的依据。

**技术：** Go、React 19、TypeScript、react-markdown、Vite、Mermaid、Playwright。选定依赖前核对许可证、安全说明、浏览器兼容和包体积，将明确版本写入 package.json 和 lockfile。

## 一、范围和边界

- 本期覆盖客户端 Agent 的回答；不改变独立安装的 XiaoTao Skill 在其他宿主中的默认行为。客户端内置 Core 提供通用风格，客户端 voiceNotice 在每轮注入，应与之保持一致。
- 首版支持 Mermaid 流程图 flowchart 和时序图 sequenceDiagram；架构图用流程图及分组表达，不承诺所有图种。比较关系优先使用已有 Markdown 表格。
- 不实现长会话压缩、并行写入、画板、交互式代码执行或 AI 生图。上轮完成的只读并行与减少进度请求属于已有工作；接手时保留工作区已有未提交修改，包括 xt-client/VERSION，不得重置或覆盖。
- 用户指定格式、篇幅和用词时优先遵守；简短不能遗漏风险、未完成项或依据。不要虚构项目事实，别强制表情和口头禅。
- 画图是辅助表达，不强制每次回答都有图。用户明确要求画图时优先响应；信息不足要标明未知，不把推测画成事实。

## 二、回答与画图规范

调整 xt-client/internal/agent/service.go 的 voiceNotice，确保关联项目、未关联项目、首轮和续聊均生效；同时检查 core.go 的精简守卫和 xt-skills/xiaotao/SKILL.md，避免指令冲突。建议规则如下：

> 像同事聊天一样自然说话。先直接回答用户真正问的问题，再按需解释原因。简单问题用简短段落，不为格式而列条目。默认不主动展开脚本名、路径、内部状态和实现流程；当用户要求操作、排查、核实来源或细节是结论所必需时提供。用户要求深入就充分展开；必要的边界、风险、未完成项和不确定性不能省略。不装熟、不强行卖萌、不说空泛套话。

选图规则同时进入正式提示：

> 用户要求画图，或关系、流程用图明显更容易理解时，选择 Mermaid 流程图或时序图；比较优先表格。一图只突出一个问题，先画主线，节点用简短易懂的中文，尽量减少交叉和堆砌，复杂内容拆图。必要时用一句话说明最重要的关系。只依据已知事实画图，未知和推测要标明。将 Mermaid 放入语言标记为 mermaid 的 Markdown 代码块。

风格评估样例：问“现在会自进化吗”，理想回答先说“能发现和记录问题，但不会自己改规则或代码”；仅在真实查证后才能说明当前项目是否已有记录，默认不展开脚本路径。追问“怎么实现的”时再给具体流程和文件。不能通过硬编码问题或固定回复模拟效果。

画图约定：一图一主题，建议主要节点 4–8 个但不作为硬限制；从左到右或从上到下，箭头方向明确，必要时标条件和结果。节点写“读取项目文件”等易懂名称，技术细节按需补充。使用有限一致的颜色，警示状态同时用文字区分；图旁用一句话解释关键关系。用户要求细节时，不为减少节点遗漏重要事实。

## 三、前端设计

### 入口和数据流

- xt-client/frontend/src/features/agent/AgentPage.tsx 的 MessageRow 和 RunTimeline 分别使用 react-markdown。抽取共用 AgentMarkdown（建议新建 AgentMarkdown.tsx），两处使用同一套插件和代码块组件，保证普通 Markdown、代码块、列表、表格、引用选择和历史消息行为不变。
- 新增 MermaidDiagram.tsx 和局部样式，放大查看复用现有 ModalFrame/ModalPresence，通过 Portal 挂到 body；保持页面正文宽度规则。
- 更新 xt-client/frontend/package.json 及 package-lock.json；Mermaid 打包进客户端，运行时不从 CDN 下载。优先动态加载，普通文字会话不加载图表库。

### 流式渲染和状态

1. 图源是不可信文本。仅识别 fenced code block 的语言标记 mermaid，普通代码和行内 code 保持原样；覆盖当前正式回复及历史回复。
2. 流式输出未闭合时不渲染、不报语法错误，显示“正在生成图示…”或原始源码。闭合检测要遵循 Markdown 围栏规则，包括反引号、波浪号、长度与缩进，不能靠简单字符串查找。闭合后渲染完整源码；后续流片段、切换会话、历史加载和主题切换不得让旧异步结果覆盖新结果；避免每个 token 都重渲染。
3. 每个图块有独立加载、成功和失败状态；每个图使用唯一 ID 避免 SVG 定义互相覆盖。内容更改或组件卸载后丢弃过期结果。可以按源码、主题和配置缓存结果。
4. 语法错误、依赖加载失败、超限或不支持的图种显示简短原因与纯文本源码并提供复制，不影响正文及其他图。原始 Markdown 持久化，重启、复制和引用时不丢失。验证流式 RunTimeline 切换到历史 MessageRow 不重复或丢图。

### 安全、性能和视觉

- 启用 Mermaid 严格安全模式，禁止脚本、HTML 事件处理器、危险链接和图内交互；不得使用 loose 模式或直接将未经净化的 SVG 插入 DOM。评估所选 Mermaid 版本 API 和 SVG 安全边界，对最终内容使用经过验证的 SVG 白名单净化或等效强隔离。禁止图内配置覆盖应用主题、安全配置和外链行为。
- 限制单图源码长度和复杂度，限制同时渲染数量；具体阈值结合正常示例与性能测试确定并写入文档，超限回退源码。不能声称普通主线程超时能中断同步计算；需要时用可终止 Worker 等隔离方式避免页面卡死。
- 按现有 data-theme 同步深浅主题，保证文字和背景对比度。默认保持可读字号，超宽图横向滚动，不强行缩到不可读。
- 图块提供键盘可用的放大查看、查看源码和复制源码；放大弹窗支持 Escape、焦点循环及恢复，复制失败有提示；尊重减少动态效果。提供无障碍名称与源码入口，SVG 不应是唯一可访问内容。

## 四、实施步骤与验收

### 任务 1：回答与选图提示

1. 阅读 service.go、core.go、xt-skills/xiaotao/SKILL.md 和相关测试。调整 voiceNotice 及必要的提示测试，覆盖有项目/无项目、首轮/续聊；不锁定大段提示全文，也不增加额外模型请求。
2. 在 xt-client 运行 go test ./internal/agent，预期通过。
3. 用可用真实模型人工评估“会自进化吗”“怎么实现”“分析风险”“画流程图”，记录模型、输入及结果。mock 不证明文风，未做真实模型验收要如实标明。

### 任务 2：Markdown 和安全图组件

1. 抽取共用 Markdown 组件，先验证无图场景一致；接入图组件、按需加载、源码回退与隔离。
2. 对合成流测试未闭合/闭合、多个图、独立错误、快速切换主题和会话、卸载后的异步返回、普通代码块。检查回答完成及重开历史时的渲染。
3. 在 xt-client/frontend 运行 npm run build，预期 TypeScript 和 Vite 通过；确认不访问 CDN，记录前端构建包体积变化。

### 任务 3：交互、安全和视觉

1. 新增 xt-client/frontend/tests/agent-mermaid.browser.test.mjs，遵循现有 Playwright 本地 Vite 和 API 拦截方式，不连接真实服务。
2. 覆盖流程图、时序图、两个图互不干扰、语法错误/超限、未闭合代码、异步过期结果、深浅主题切换、窄屏、键盘和弹窗焦点恢复、复制失败、正常代码块；验证恶意脚本、事件属性、javascript 链接和外部请求不会执行。不要以字符串测试冒充实际渲染测试。
3. 在 frontend 运行 node --test tests/agent-mermaid.browser.test.mjs、npm run test:timeline、npm run test:history。人工检查浏览器下典型图的深浅主题和窄窗口，确认节点、文字、箭头清楚；WebView2 桌面实测单独报告，不拿无头测试冒充桌面验收。

### 任务 4：整体验证和文档

1. 在 xt-client 运行 go test ./... 和 go vet ./...，在仓库根目录运行 node tools/agent-rules.mjs check。若 AI 需要构建 EXE，只运行 ./build.ps1 -Verify，不递增版本或覆盖正式产物，不自行停止运行实例。
2. 更新 xt-client/README.md 和 docs/architecture/xt-client-agent.md；如命令或模块职责变化，按仓库规则同步规则源及生成文件。说明支持图种、错误回退、生成图准确性边界和实际验收状态。
3. 用“Agent 运行过程”“代理账号选择”“安全审批”作为真实项目案例；先查代码再画图，人工核对关系、主线可读性和源码。记录未实测项，不捏造测试或提速数据。
4. 收尾检查可复用规则候选；只有有证据的经验才按项目规则记录，交付时说明文档更新和候选情况。

## 五、交付标准

- 普通回答更贴合用户问题，用户要细节时仍充分展开；不额外调用模型润色。
- 完整 Mermaid 流程图和时序图在当前回答与历史中可读、可恢复、可查看和复制源码；流式未完成、错误及超限输入有清晰回退。
- 深浅主题和窄窗口可用，放大及源码操作支持键盘；不可信图内容不得执行脚本或触发任意网络请求。
- 自动检查通过，真实模型、视觉及桌面验收覆盖和限制如实报告。
