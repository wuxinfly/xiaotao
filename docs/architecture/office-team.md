# 办公室团队与 3D

## 权威数据

- 环境级 `collaboration/roles/registry.yaml` 保存可跨项目复用的全局角色。
- 项目 `.xiaotao/roles/registry.yaml` 保存项目角色，`.xiaotao/team.yaml` 保存当前成员关系。
- `office.db` 继续保存任务、消息、产物、审批、角色会话和历史；它不是角色注册表，也不会随移出/归档删除。
- 字段与样例见 `docs/office/roles/README.md`。所有写操作经客户端服务，校验当前 revision、角色引用和完整项目索引；正式版/UAT 环境隔离。

## 行为边界

办公室成员不是旧固定“设计师/开发者”的换皮。稳定 `role_...` 连接身份、外观和只读会话，只有当前项目成员能开始新对话。模型偏好必须属于当前客户端模型目录；缺失时不静默换模型。成员对话与首页共享富文本编辑器和 Markdown 转换，分别使用各自的模型选择和消息接口。

“产品实现小队”只生成可编辑的角色草稿。成员聊天保持只读；用户明确确认后，当前成员可以通过独立任务会话接单，使用同一 Agent 内核、工具、审批及当前访问模式。同一成员同时只有一个未结束任务，没有自动交接、流程执行或并行 Worker。旧固定会话只读保留，不自动迁移；旧小涛任务不猜测绑定新角色。全局角色跨项目共享配置，不复制对话、任务、产物或项目记忆。

任务 JSON 保存可选 `memberId`、来源 `chatSessionId` 和有界讨论交接。成员身份由办公室服务从当前团队验证后注入 Agent 会话，通用会话创建接口清除该字段。任务事件经同源 `/api/office/tasks/{id}/events` 订阅，只作实时视图，权威状态仍在持久记录。

项目成员变更使用 `/api/office/team`、`/api/office/team/bootstrap` 和 `/api/office/roles*` 同源 API；冲突返回 409，损坏返回 422。全局角色归档前必须验证全部已登记项目的引用，验证失败则拒绝。

## 场景与团队解耦

3D 场景由已选项目驱动，独立于团队注册表请求；成员、任务和资料仍以当前项目的办公室快照为准。未建队项目也有 3D 和快照返回的内置小涛。小涛作为固定角色可直接接收只读对话，不依赖团队登记；其他角色必须是当前项目的在用成员。组队属于可选操作，二维列表用于 WebGL 或本地模型失败后的降级。房间、资料架和四种角色造型由前端脚本生成到同一个本地 GLB；浏览器端在项目切换和退出时释放渲染资源。交互与验收见 [办公室工作台改版](../plans/2026-11-14-office-workspace-refresh.md)。

工位、桌椅和角色关节由同一个 GLB 提供。前端按快照中的稳定成员 ID 分配工位：内置小涛单独占用窗边桌，其他成员和未结束任务的执行分身使用可扩展工位。任务结束后分身和工位一起移除。走动、落座、灯光均由渲染端维护，不写入业务状态，不改变任务派发；办公室直接用灯光、窗景材质和背景体现深浅主题，不单独显示昼夜标签。详见 [工位、动作与日夜](../plans/2026-11-14-office-workstations.md)。

## 后续独立变更

只读 Skill 消费尚未接入；流程执行、Worker 生命周期和自动交接另建变更。不得在这些注册表职责文本中写入 shell、流程名或工具名，并期待获得权限。

3D 画布铺满主导航下方，顶部的项目操作和底部的场景控件悬浮在画布上。任务与团队从右侧抽屉打开，覆盖画布而不改变其尺寸。成员会话复用首页消息和输入框组件，仍通过办公室只读会话接口。资料详情独立盖在资料馆上，底层保留筛选状态并暂停键盘交互；Markdown 文本复用首页正文排版。交互验收见 [办公室交互细化](../plans/2026-11-14-office-interaction-polish.md)。
