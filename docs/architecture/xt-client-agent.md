# 小涛 Agent 会话运行内核

日期：2026-11-01。

状态：首个可运行闭环已实现。现已支持多个会话并行，每个会话保留单工作目录、单执行者，伙伴、工作流和独立沙箱尚未实现。

## 多会话并行（2026-11-05）

前端将短时导航请求状态与每会话执行状态分离，保留各自 SSE 请求、会话缓存和草稿。流事件按 session ID 更新缓存及侧栏，只有当前会话事件更新正文；切换不会取消流。历史补齐合并旧消息，停止请求带当前会话 ID。安全确认按队列逐个呈现，不因另一个会话正在确认而自动拒绝。

Service 继续以 runs[sessionID] 管理取消函数，仅拒绝同会话重入；运行记录保存项目和任务标题，每轮模型调用在 system 指导中刷新同项目其他任务摘要，摘要按不可信数据处理。不同会话共用目录，不使用 worktree，也不提示正常并发。文件工具保存读取/写入时的 SHA-256 摘要，写入已有文件前必须先读；检查到变化或删除就返回冲突供模型重新读取合并。进程内文件工具共用短时互斥锁，避免两个工具同时通过旧摘要检查；不锁住整个任务，也不阻止先后编辑同一文件。命令、脚本、外部编辑器不参与此锁，因此不能声称文件系统完全隔离或原子防冲突。刷新窗口仍没有后台恢复保证。

实现计划和验收记录见 [多会话并行](../plans/2026-11-05-multi-session.md)。

## 目标与边界

小涛可以在用户选择的项目或默认工作目录里完成一件事：理解要求、读取代码、修改文件、运行验证，并允许用户随时停止。客户端不再把 Agent 页面作为占位页，也不需要 Codex 或其他编码工具作为运行宿主。

本版明确不包含：

- 伙伴页面、跨任务调度或并行 Worker。
- 工作流编排、跨会话自动恢复和长期记忆提炼。
- 操作系统级沙箱、工具级细粒度授权或网络隔离。
- 通用 Skill 市场、下载与自动安装/更新。内置 XiaoTao Core 和显式目录的本地 Skill 发现已接入，具体加载方式见下文。

## 运行结构

### 内置 XiaoTao Core

客户端将 `xt-skills/xiaotao/` 的完整文本资源（SKILL、references、schemas、workers 与 Python 脚本，排除 Python 缓存）打包进 EXE。`node tools/bundle-core.mjs` 或 `go generate ./internal/agent` 更新 `internal/agent/core.json.gz`；`build.ps1` 构建前自动刷新。资源源文件仍唯一维护在 xt-skills，不手改压缩包。

每次发送前，在当前环境的 Agent 数据目录 `core/<资源摘要>/` 校验并释放资源，失败则返回错误，不回退成精简人设。新会话首次请求的 system 消息包含完整 SKILL.md；后续请求改用精简守卫和 Core 绝对路径，模型通过 read_file 按当前步骤加载完整核心与 Reference，不将全套参考资料永久塞入上下文。项目 AGENTS 指令继续每次读取并追加。

完整规范可用不代表宿主新增执行能力：仍无独立 Worker、Hook、自动压缩及后台恢复，需如实使用 in-session-fallback；记忆脚本使用通用入口，需要本机 Python，缺少时必须报告限制。客户端不执行 Codex 专用 Hook 回执，也不自动创建项目记忆或全量扫描 Catalog。已有会话下次发送即获得守卫和完整资源入口；新会话首次完整注入。正式版和 UAT 各自释放资源，不共享运行状态。

验证：自动测试覆盖核心原文一致、关键脚本/参考资料完整、后续请求精简、安装副本修复及环境路径隔离；真实模型按需读取、Python 保存与桌面新包仍需实测。

### 本地第三方 Skills（2026-11-06）

`internal/agent/skills.go` 将当前环境 `agent/skills.json` 的显式目录配置与有界发现分开。目录支持自身 SKILL.md 或一级子目录；扫描只解析 UTF-8 YAML 元数据，不运行脚本、不自动发现其他工具目录、不跟随越出根目录的链接。实际文件路径摘要作为稳定 ID，重叠目录去重；启用技能同名时全部排除直到用户解决，小涛同名候选不能覆盖内置 Core。

每次 Send 在 Core 后追加启用技能的 name/description/绝对路径 JSON 索引及诊断，第三方正文不预载。模型按请求或描述匹配后使用现有 read_file 读取全文与相对引用，不新增工具、不改变访问模式和命令审批。禁用控制可用索引，不是文件访问隔离；脚本依赖与授权需执行前核对，扫描不会安装任何依赖。所有技能移除后仍明确告知模型不要从历史恢复旧索引。索引按单次发送固定，设置变化从下次发送生效。

GET/PUT `/api/agent/skills` 与 POST `/api/agent/skills/scan` 均为同源管理接口，草稿扫描不保存，配置用临时文件同步后替换。正式版/UAT 的数据根保持独立；损坏配置明确失败，个别目录/元数据错误形成诊断，不影响其他可用技能。扫描和上下文均有容量上限与遗漏提示，详见 README。

React 设置新增 Skills 页签，沿用 ModalFrame、海洋主题和键盘焦点；支持路径输入、桌面选目录、目录与单项开关、扫描、错误重试和保存反馈。源码与机械流程测试不等于模型一定选择/遵循技能，真实账号与桌面原生目录选择仍按人工场景验收。

```text
React 工作台
  ├─ 项目目录选择与模型选择
  ├─ 消息流、执行进度、停止
  └─ SSE 接收过程事件
        │ 管理接口（同源校验）
        ▼
Go Agent Service
  ├─ 会话持久化
  ├─ 模型工具循环（最多 40 轮）
  ├─ 取消、错误和运行状态
  └─ 工具执行
        ├─ list_files
        ├─ search_files
        ├─ read_file
        ├─ write_file
        └─ run_command
              │
              ▼
        当前项目目录
```

输入框左下角的访问模式对当前环境所有会话生效并持久化，默认为安全模式。安全模式识别到常见高危命令或覆盖至少 128 KiB 的文件时通过事件请求确认，批准后执行，拒绝结果回传模型；停止任务会取消等待。完全访问模式允许自主执行。两种模式都支持跨目录访问，运行权限取决于客户端进程用户；命令识别无法覆盖所有高危操作。

模型回复通过 SSE 按片段更新同一条消息，完成后持久化；停止或断流时保留已收到的文本。工具调用按索引或 ID 拼装，参数完整且流正常结束后才执行。

模型调用不直接访问上游，而是通过本地服务自己的 `/v1/chat/completions`。这样 Agent 与账号路由、模型目录和用量统计共用同一条入口，后续替换或增加模型来源时不需要改 Agent 页面。

## 关键技术决策

| 决策 | 选择 | 理由与代价 |
| --- | --- | --- |
| 内核语言 | Go | 延续本地服务，交付无需 Python/Node.js；模型与工具循环需自行维护 |
| 执行模型 | 流式模型回合 + 工具循环 | 文本片段实时展示，工具参数拼装完整后执行；断流保留已显示文本且不执行不完整工具调用 |
| 传输 | 管理 API + SSE | 用户消息、工具开始/结束和最终答复能及时推送；断线后以会话快照为准 |
| 会话存储 | 用户数据目录下 SQLite | 会话摘要与消息、执行记录分开读取；旧版 JSON 首次使用时导入 |
| 工具范围 | 读、搜、写、跑命令 | 能形成软件任务闭环；首版不做跳转编辑器、Git 专属工具和后台任务 |
| 工作目录 | 默认解析位置，支持绝对路径和跨目录访问 | 在当前用户权限范围内读写 |
| 危险命令 | 全局安全模式识别常见高危命令并等待确认；完全访问模式不逐项确认 | 识别不完整，不是系统级沙箱 |
| 取消 | context 贯穿模型请求和命令 | 停止按钮能中断当前请求/进程；不保证外部程序派生的全部子进程立即消失 |

## 会话与事件

Agent 请求本地模型代理时读取当前代理密钥，密钥轮换后的请求使用新密钥。会话包含工作目录、模型、消息、工具活动和最终状态。页面发送首条消息时创建会话；项目可选，未选时使用数据目录下的 agent/workspace/，与数据库及账号数据分开。会话数据保存在 agent/agent.db SQLite 数据库中，首次使用时事务导入 agent/sessions/*.json 并保留原文件；导入失败时保留原文件并报错。正式版与 UAT 各自保存。消息角色包括 `user`、`assistant`、`tool`；工具结果保留调用 ID，下一次模型回合会拿到完整工具上下文。工具活动记录本次任务读取了什么、修改了什么、运行了什么，用户不需要查看模型原始 JSON。

页面切换时保留 Agent 工作台状态。侧栏通过 `/api/agent/sessions?summary=1` 读取摘要，选中会话后通过 `/api/agent/sessions/{id}/history` 读取最近历史；原列表接口与详情接口仍支持完整会话。模型目录单独加载，切回时刷新。

输入区以 Tiptap 文档结构为唯一草稿来源，发送时序列化为 Markdown。普通段落 Enter 发送，Shift + Enter 插入硬换行，Ctrl/⌘ + Enter 强制发送；标题、引用、列表和代码块内 Enter 交给编辑器。顶层列表空项再回车退出为普通段落，嵌套列表空项先退回父列表项；代码块按编辑器规则换行并在空行退出。空列表项不触发发送，任务运行中 Enter 不发送且保留草稿。支持并已实测列表、有序列表、嵌套列表、标题、引用、粗体、斜体、行内代码、代码块和分割线。

输入区另支持 `@` 引用直接对话。Tiptap inline node 保存环境内来源 ID，正文只保留可读标签；发送请求带 `references` 会话 ID 数组，服务端不解析正文。只有引用标签、没有正文时也允许发送。引用快照在用户消息落库前读取并冻结，限制 5 个来源、单来源 64 KiB、合计 128 KiB，只收录用户和助手文字，不收录工具原始输出。快照记录最后消息位置、来源更新时间和摘要，历史读取时补全来源删除及后续更新状态。

模型上下文在本次用户消息前注入一份引用摘要，旧轮次不重复带入冻结全文。首版摘要由冻结文字确定性截取，不额外调用模型；后续可按真实效果替换为缓存摘要。`read_conversation_reference` 仅在当前消息有直接引用时声明，只接受这些快照 ID，按关键词返回有界片段，不递归读取来源中的其他引用。现有 `/messages` 不带 `references` 时维持原行为。

选中同一条小涛回复中的文字后，选区旁显示“引用”；支持多段引用，输入框使用紧凑标签展示并支持悬停查看。发送前原文对应位置高亮并显示编号，点击编号可编辑引用文字、填写该引用的回复或移除引用。发送时将各引用及对应回复作为带来源标记的 Markdown 内容写入用户消息；服务端确认接收后移除对应标记，切换会话会清除草稿。

聊天消息按 Markdown 渲染，代码围栏显示为可横向滚动的代码块，保留普通文本换行；不执行消息中的原始 HTML。
时间线以用户消息划分轮次；每轮最后一条工具活动及之前的工具、助手说明合并为一个过程面板，按时间展开查看。最后一条工具活动之后的助手回复保留在正文，纯文字轮次不生成面板。实时事件、结束后的历史补齐和重新打开会话共用该分组规则，避免迟到的中间说明将单个面板拆散。分页缺少轮次边界时先按已加载记录分组，加载更早记录后重新合并。

过程面板左侧的步骤连线穿过中间说明，保持前后步骤连续；开头说明不向上延伸连线。

过程分组回归：在 `xt-client/frontend` 执行 `node --test tests/agent-process.browser.test.mjs`。测试隔离全部 API，模拟 SSE 先到、工具间文字随后由历史补齐，验证卡片节点保留、结束折叠、展开后的说明与步骤顺序、刷新重开及窄窗口下仍保持单卡片。真实 WebView2 任务结束后的效果仍待人工验收。
过程面板与助手回复共用头像，默认折叠并展示最新动态和耗时，用户可展开完整步骤；结束时自动收起并在下方显示回复。总耗时优先按用户消息到助手回复计算，缺少边界时以可用活动时间计算，不能计算时显示未知。仅用户仍在消息区底部时自动跟随新内容。
展开的步骤列表通过挂载到 body 的浮层展示，不改变对话布局；浮层限制高度并在面板内滚动，支持点击外部或 Escape 关闭，失败状态保留在对应步骤中。
浮层展开和收起使用短暂的透明度及位移过渡，关闭时立即停止交互；减少动态效果时取消过渡。

常用模型的 ID 和显示名称缓存在本地浏览器存储，工作台直接读取缓存，打开设置时才请求完整目录；目录不完整或请求失败不清除已有选择。旧版只保存 ID 的设置继续可用，保存后补充名称。实际调用仍由代理校验账号和模型可用性。

输入区外左上角显示当前项目，项目弹窗负责目录与显示名：桌面壳调用 Windows `IFileOpenDialog` 的目录模式，由原生窗口命令异步启动选择器，并把路径或错误回填到 WebView；不使用 WebView2 的同步 RPC 等待。浏览器入口提示使用桌面客户端选择目录；确认时服务端校验目录是否存在，显示名随会话持久化。右下角的模型选择只读取 Agent 设置中勾选的常用模型；设置弹窗按来源展示完整聚合目录，支持搜索、单项和分组全选，选择保存在本机 `localStorage`。两者使用 `createPortal` 挂到 `body`，支持 Escape、焦点约束和遮罩关闭。

任务状态为 `idle`、`running`、`completed`、`failed`、`canceled`。服务重启时，遗留的 `running` 会话在任务列表读取时标为失败，并说明“上次任务因服务退出而中断”，不伪装成自动恢复。

## 工具接口

每次发送消息时，内核从所选工作目录根部读取项目指令：优先非空的 `AGENTS.override.md`，其次 `AGENTS.md`，加入模型的系统消息。指令文件须是 UTF-8 普通文件，最大 32 KiB；读取异常或超限时直接返回错误。不存在或内容为空时跳过，每次发送重新读取。子目录中的指令由模型按提示自行查找，尚无自动发现或强制执行；不加载项目外全局指令和备用文件名。项目指令不会改变工具的路径或命令限制。

| 工具 | 用途 | 主要限制 |
| --- | --- | --- |
| `list_files` | 列出项目文件和目录 | 跳过隐藏目录、`node_modules`、`vendor`、`dist`；最多 500 项 |
| `search_files` | 在项目文件中做字面搜索 | Windows 当前使用隐藏窗口的 PowerShell；最多返回 80 个文件命中 |
| `read_file` | 带行号读取文本文件 | 单文件最多 512 KiB，单次最多 400 行 |
| `write_file` | 新建、覆盖或追加 UTF-8 文本 | 支持绝对路径和相对工作目录的路径，自动创建父目录 |
| `run_command` | 在项目根目录运行非交互式命令 | Windows 后台执行不显示控制台窗口；默认 120 秒、最多 600 秒；输出最多 80 KiB；安全模式下常见高危命令需确认 |

模型每次只能通过工具声明操作，系统实际执行前再做目录和命令检查。工具提供的是能力说明，不是权限授予。

Agent 的项目选择、模型选择、排列方式与会话操作菜单复用项目级 `Popover` 外壳，业务列表与操作仍由页面提供。外壳统一挂载到 body、根据触发控件或右键坐标定位，空间不足时翻转并限制在视口内；统一外部点击、Escape、选项键盘导航及初始焦点。展开采用 210ms 轻移缩放，收起采用 160ms 反向过渡，关闭内容立即 inert，减少动态效果时仅保留淡入淡出。

## 历史分页与渲染（2026-11-03）

`SessionList.tsx` 将项目标题和展开会话铺平为固定高度行（34px / 56px），用二分定位可见范围，预留上下 280px；焦点行与菜单行额外挂载，项目折叠后移除会话节点，箭头保留双向过渡。列表独立 memo，排序、分组及行索引缓存。历史 `MessageRow` 按 ID、角色、正文与过程归属缓存，输入和计时不重解析旧 Markdown；时间线仅消息或活动变化时重建。

历史 API 返回 `{session, before}`。`before` 为空表示没有更早数据；请求省略 `before` 时读取最近一批。游标为消息位置和活动位置的两个排他上界；读取使用现有 `(session_id, position)` 主键，在同一只读事务中获取元数据和两条记录流，再按时间合并，单页最多 80 条。首次页冻结两条流的尾位置，翻页期间追加记录不会改变已发游标；相同时间记录由流类型和存储顺序稳定处理，不依赖时间戳唯一性。JSON 记录总量软上限 256 KiB，但至少返回一条完整记录，因此单条巨型记录仍可能超过上限。每条流按自身存储顺序读取，不更改原始历史；模型执行仍调用原完整会话读取链路。

前端按 ID 合并分页和 SSE 数据，保留已加载范围。历史请求带本地代次检查，切换会话或发送后忽略旧响应；加载状态、错误提示和历史插入前后通过布局阶段的高度差补偿保持滚动位置。用户向上查看时不跟随新事件，发送和切换会话时恢复底部跟随。页面边界允许落在连续活动中，向上加载后重组为连续过程；首批缺少完整轮次边界时，只按当前可用记录计算耗时。

自动化新增：Go 覆盖空历史、单流、相同时间、完整遍历、追加记录游标稳定性、超长记录不截断、非法游标和 API 同源检查；`frontend/tests/history.browser.test.mjs` 使用 Edge 无头浏览器和全部 API 拦截的合成数据，验证 1 万条会话下节点小于 35 个、折叠卸载、Home / End / 方向键、菜单 Escape、80→100 条历史追加、失败重试位置保持、输入保留历史 DOM、发送保留历史及迟到响应隔离。

待验收：真实数据的大体量打开耗时与滚动帧率、WebView2 桌面壳、缩放和窄窗口、执行活动跨页的复杂组合。正文仍未实现动态高度虚拟滚动，持续加载会累积节点；摘要仍全量读取。根据真实长会话测量再决定第三阶段。


项目侧边栏（2026-11-04）：项目仍按目录分组，项目行提供预填项目的新会话入口与 Portal 操作菜单。`PATCH /api/agent/project/name` 事务更新同目录会话的项目显示元数据，保留历史及更新时间，运行中项目拒绝修改；`POST /api/agent/project/open` 检查目录后通过 Windows ShellExecute 打开资源管理器，两者均校验同源。

## MCP 浏览器与扩展

MCP 活动记录额外保存 `tool`（服务/原工具名）、`input` 与 `output` 预览，不使用任务内 `mcp_N` 别名作用户展示名。常见浏览器工具映射中文动作，未知名称原样回退；参数摘要只取 URL、页面或元素等目标字段。运行与完成事件、历史记录共用这些字段，前端可展开查看；输入和结果预览各限 6000 字符，非文本内容不复制 base64 数据，完整模型工具回传不变。旧活动缺失字段仍兼容，不根据临时编号重建工具身份。

Agent 设置提供“MCP 工具”页签，通过同源 GET/PUT `/api/agent/mcp` 管理当前环境 `agent/mcp.json`；自定义服务支持 command、args 和 disabled。Chrome 浏览器为默认启用的内置 MCP，读取和保存配置时自动合并，不能删除、禁用或覆盖启动配置；无需用户添加，空配置仍保留浏览器。本地文件优先，缺失时兼容进程环境变量 `XIAOTAO_MCP_CONFIG`，界面另存不回写外部配置。正式版与 UAT 各自保存，不从项目读取、不跨环境导入。每次任务获取配置快照，初始化和发现工具后加入模型工具循环；后续修改不影响运行中连接。POST `/api/agent/mcp/test` 测试单个草稿服务，仅发现工具，整体限时 35 秒并清理进程，不保存、不执行工具。安全模式逐项确认模型工具调用，取消与超时终止服务。配置和限制见 xt-client README 的 MCP 小节；图片结果尚未转为视觉消息，不包含桌面操作。
