# 小涛 Agent 单任务运行内核

日期：2026-11-01。

状态：首个可运行闭环已实现。范围是单任务、单项目、单执行者，伙伴、工作流和独立沙箱尚未实现。

## 目标与边界

首版先证明小涛能在用户选择的项目里完成一件事：理解要求、读取代码、修改文件、运行验证，并允许用户随时停止。客户端不再把 Agent 页面作为占位页，也不需要 Codex 或其他编码工具作为运行宿主。

本版明确不包含：

- 伙伴页面、跨任务调度或并行 Worker。
- 工作流编排、跨会话自动恢复和长期记忆提炼。
- 操作系统级沙箱、工具级细粒度授权或网络隔离。
- Skill 市场与自动安装。现有小涛人设进入系统提示词；完整 Skill 发现和按需加载尚未接入。

## 运行结构

```text
React 工作台
  ├─ 项目目录选择与模型选择
  ├─ 消息流、执行进度、停止
  └─ SSE 接收过程事件
        │ 管理接口（同源校验）
        ▼
Go Agent Service
  ├─ 会话持久化
  ├─ 模型工具循环（最多 40 轮）
  ├─ 取消、错误和运行状态
  └─ 工具执行
        ├─ list_files
        ├─ search_files
        ├─ read_file
        ├─ write_file
        └─ run_command
              │
              ▼
        当前项目目录
```

模型调用不直接访问上游，而是通过本地服务自己的 `/v1/chat/completions`。这样 Agent 与账号路由、模型目录和用量统计共用同一条入口，后续替换或增加模型来源时不需要改 Agent 页面。

## 关键技术决策

| 决策 | 选择 | 理由与代价 |
| --- | --- | --- |
| 内核语言 | Go | 延续本地服务，交付无需 Python/Node.js；模型与工具循环需自行维护 |
| 执行模型 | 非流式模型回合 + 工具循环 | 工具调用和错误处理清晰，先保证可完成；模型文本不是逐 token 展示 |
| 传输 | 管理 API + SSE | 用户消息、工具开始/结束和最终答复能及时推送；断线后以会话快照为准 |
| 会话存储 | 用户数据目录下 JSON 会话 | 当前单用户任务足够，便于排查；高频历史或全局检索成熟后再迁移 SQLite |
| 工具范围 | 读、搜、写、跑命令 | 能形成软件任务闭环；首版不做跳转编辑器、Git 专属工具和后台任务 |
| 目录边界 | 解析后必须位于所选项目内 | 能拦截常见越界；不宣称抵御恶意软件、符号链接竞态或系统级攻击 |
| 危险命令 | 明显破坏性命令拒绝 | 防误操作；不是完整命令安全策略，仍需用户确认高风险操作 |
| 取消 | context 贯穿模型请求和命令 | 停止按钮能中断当前请求/进程；不保证外部程序派生的全部子进程立即消失 |

## 会话与事件

会话包含项目、模型、消息、工具活动和最终状态。消息角色包括 `user`、`assistant`、`tool`；工具结果保留调用 ID，下一次模型回合会拿到完整工具上下文。工具活动记录本次任务读取了什么、修改了什么、运行了什么，用户不需要查看模型原始 JSON。

任务状态为 `idle`、`running`、`completed`、`failed`、`canceled`。服务重启时，遗留的 `running` 会话在任务列表读取时标为失败，并说明“上次任务因服务退出而中断”，不伪装成自动恢复。

## 工具接口

| 工具 | 用途 | 主要限制 |
| --- | --- | --- |
| `list_files` | 列出项目文件和目录 | 跳过隐藏目录、`node_modules`、`vendor`、`dist`；最多 500 项 |
| `search_files` | 在项目文件中做字面搜索 | Windows 当前使用 PowerShell；最多返回 80 个文件命中 |
| `read_file` | 带行号读取文本文件 | 单文件最多 512 KiB，单次最多 400 行 |
| `write_file` | 新建、覆盖或追加 UTF-8 文本 | 只能是项目内路径，自动创建父目录 |
| `run_command` | 在项目根目录运行非交互式命令 | 默认 120 秒、最多 600 秒；输出最多 80 KiB；明显破坏性命令拒绝 |

模型每次只能通过工具声明操作，系统实际执行前再做目录和命令检查。工具提供的是能力说明，不是权限授予。

## 当前验收

自动化覆盖：

- 项目内读写、行号读取、父目录越界和绝对路径拒绝。
- 命令在项目根目录执行、超时上下文和明显破坏性命令拒绝。
- 模型 HTTP 客户端解码工具调用和后端错误。
- 模型首轮选择工具、系统执行并写盘、工具结果回到模型、最终答复写入会话。
- 工具循环轮数上限、会话路径 ID 校验和遗留运行状态处理。
- 前端 TypeScript 与 Vite 构建。

已验证：

- 独立验证实例的真实 `/api/agent/models`、`/api/agent/sessions`、`/api/agent/project`。
- 1159px 三栏和 770px 双栏工作台截图，页面高度、右侧设置栏和底部输入框均未裁切。
- Windows WebView2 桌面窗口的实际显示，主标题、项目/模型设置、执行进度和输入区完整。
- 已知视觉残留：WebView2 桌面窗口首次进入时会遮住空态顶部的“START A TASK”小标签上边缘；浏览器无此问题，核心信息和操作不受影响。需在桌面壳渲染层继续定位。

尚未验收：

- 真实账号在 Agent 页面完成真实代码修改的端到端任务。
- Windows 文件夹选择框在桌面窗口中的实际交互。
- 缺少 WebView2 时的 Agent 页面回退。
- 长任务、命令产生大量输出、进程取消和多工具并发的压力测试。

## 后续优先级

1. 用真实项目做验收，记录小涛在搜索、修改、验证上的成功和失败模式。
2. 接入小涛 Skill 发现与按需加载，明确第三方脚本依赖提示。
3. 把工具权限分成只读、项目写入、命令执行和外部动作，并设计确认界面。
4. 基于相同内核设计伙伴；先支持有边界的只读调查，再做可写并行。
5. 会话数量和检索需求明确后，再迁移到 SQLite 或统一任务存储。
6. 评估操作系统级沙箱，不能把当前路径拦截描述成强隔离。
