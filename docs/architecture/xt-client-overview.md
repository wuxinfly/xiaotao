## 1. 产品定位与阶段范围

小涛客户端包含自研 Agent 和统一模型入口两部分。模型代理与管理已形成可运行底座，Agent 已支持多会话并行执行闭环，伙伴和工作流仍属后续阶段。

```text
小涛客户端
├─ 小涛 Agent
│  └─ 自研 Agent 的任务与交互界面
└─ 模型
   ├─ 仪表盘
   └─ 账号与配额
```

### 小涛 Agent

以现有 xt-skills 的能力和协作方式为基础，自行实现任务运行、模型调用、工具执行等流程，不依赖其他 AI 编码工具作为运行宿主。首版已支持单个小涛在选定项目内读写文件、搜索和运行验证，并提供任务持久化、取消和工具活动展示；已支持内置小涛 Core 与显式目录的本地 Skills 管理和摘要发现。伙伴、工作流、操作系统级沙箱及在线 Skill 市场/自动安装尚未实现。详见 [会话运行内核](xt-client-agent.md)。

### 模型

支持反向代理渠道，以及用户自行配置的 API 地址、密钥和模型，通过统一入口管理、启停和调用。小涛 Agent 和外部工具均可通过统一模型 API 访问这些模型。

- 仪表盘：展示实时请求、用量、运行状态和错误等。独立桌面浮窗精简展示当前请求的账号、模型、速度、耗时和今日用量，可拖动，不依赖主窗口，托盘右键菜单可开关。浮窗入口使用独立窗口布局铺满客户区，深色背景与纵向信息排列独立于页面内浮层的边距、投影和响应式断点；原生边框变更后同步 WebView 客户区尺寸。
- 账号与配额：管理渠道、账号、API 配置、登录状态和可用额度；各来源提供模型目录入口，在独立弹窗中按账号查看名称、复制完整模型 ID、刷新并区分实时与内置目录，支持 Escape、遮罩关闭和焦点归还。
- 真实上游配额与本地统计用量分别展示；上游不支持配额查询时，不把本地估算显示为真实剩余额度。

## 2. 总体架构

网页外观提供深海暗色与浅海亮色两套主题，右上角即时切换。主题模块统一管理文档根属性、本地偏好及独立请求浮窗的同源存储事件同步；入口 HTML 提前读取偏好。页面、Portal 菜单与弹窗、Toast、HUD 统一适配，原生启动动画仍使用原有外观。实现与验收见[浅海主题](../plans/2026-11-03-shallow-sea-theme.md)。

采用“Go 本地服务 + Web 页面 + 轻量桌面壳”。服务承担核心能力，桌面壳和浏览器访问同一套页面、服务及用户数据。

```text
小涛分发 EXE
└─ 启动器：检查安装、比较版本、释放或更新程序
   ├─ Go 本地服务
   │  ├─ 托管 Web 页面
   │  ├─ 提供管理 API
   │  ├─ 提供统一模型 API
   │  ├─ 管理渠道、账号、配额、配置和用量
   │  └─ 后续启动和管理 Agent 进程
   └─ 轻量桌面壳
      └─ 打开本地服务提供的页面

普通浏览器 ──→ 同一套 Web 页面
外部工具   ──→ 统一模型 API
```

启动客户端时启动服务进程，默认通过桌面壳打开页面，同时支持通过普通浏览器打开。后续 Agent 可以作为独立进程，由本地服务管理。

桌面壳启动时使用不全局置顶的原生动画封面，封面作为主窗口内的原生子窗口遮挡初始化内容，尺寸跟随主窗口客户区，并参与最小化画面；主窗口保留正常可见性，让 WebView2 正常加载绘制。首屏就绪且满足动画最短时长后关闭封面；交接时主窗口提升到普通窗口层最前面，不设永久置顶；用户已切走时不主动切换键盘焦点，已最小化时保持最小化。原生窗口与 WebView2 使用深色默认背景，15 秒未收到就绪信号则兜底交接。实现与人工验收范围见[启动窗口优化](../plans/2026-11-03-client-startup-design.md)与[浮窗及启动回归](../plans/2026-11-04-hud-visibility.md)。

自绘标题栏的主窗口在 Windows 最大化计算中使用当前显示器的工作区，按显示器原点换算位置；网页视图跟随原生客户区。多显示器及不同缩放下的桌面效果仍需人工验收。

### 技术决策及取舍

| 部分 | 已确认方向 | 理由与代价 |
| --- | --- | --- |
| 本地服务 | Go | 编译为独立 EXE，无需用户另装语言环境，适合 HTTP、SSE 和进程管理；需要移植 Python 渠道实现 |
| 用户界面 | Web 页面 | 桌面壳与浏览器共用界面；前端框架待定 |
| 桌面窗口 | 系统 WebView2 轻量壳 | 避免携带完整 Chromium；需处理机器缺少 WebView2 的情况，具体壳框架待定 |
| 分发 | 单 EXE 自动部署与启动 | 用户无需手动解压或经过传统安装向导；更新流程需处理运行中文件及失败恢复 |
| 数据存储 | 独立用户数据目录 | 程序更新不覆盖用户数据；数据库倾向 SQLite，驱动待定 |

不采用 Electron，优先控制分发包体。启动器可以使用 Go，尚未确定桌面壳是否同样使用 Go 或采用其他技术。前端静态资源可以嵌入 Go EXE，具体打包方式待定。最终包体需要以实际构建结果衡量。

建议在缺少 WebView2 时用默认浏览器打开页面，使服务和模型 API 仍可使用；运行时检测及回退策略尚待细化，不默认静默安装 WebView2。

## 3. 分发、安装与版本规则

手动打包从 `xt-client/VERSION` 读取版本并递增第三位，注入程序状态信息并生成带版本号的 EXE 副本；AI 自行验证时使用 `-Verify`，沿用版本并输出到独立目录。固定文件名仍供开发环境快捷方式使用。这尚未实现安装或版本比较。

对外分发一个 EXE，该文件携带对应版本的程序。首次双击自动部署并启动，后续双击根据已安装版本决定更新或直接启动。单文件分发不要求安装后的程序也只有一个文件。

| 状态 | 行为 |
| --- | --- |
| 尚未安装 | 释放程序到程序目录，创建桌面快捷方式，然后启动 |
| 已安装版本与启动器携带版本相同 | 直接启动已安装程序 |
| 启动器携带版本高于已安装版本 | 更新程序，保留用户数据，然后启动 |
| 启动器携带版本低于已安装版本 | 提示启动器过旧，继续启动已安装的新版本，不降级、不阻止使用 |

旧启动器提示应表达：“当前启动器是旧版，将启动已安装的最新版本，请检查是否使用了错误版本的启动器。”最终文案可在界面设计时调整。这里的最新版本指本机已安装版本，不代表已向远端查询最新发布。

桌面快捷方式用于日常启动，指向程序目录中的稳定启动入口；新的分发 EXE 用于首次部署或版本更新。版本比较规则、版本清单格式和稳定启动入口的具体实现待定。

### 绿色部署约定

- 不主动向 Windows 注册表写入小涛安装信息。
- 不登记卸载项、文件关联或注册表启动项。
- 通过程序目录和版本文件判断安装状态，不依赖注册表。
- 创建桌面快捷方式。

该约定不保证 Windows 或安全软件无法发现程序；操作系统自身的运行记录不属于应用可承诺消除的范围。

## 4. 程序与用户数据分离

| 目录 | 内容 | 更新原则 |
| --- | --- | --- |
| 程序目录 | 启动入口、服务 EXE、桌面壳、页面资源、视觉素材、版本文件及必要运行资源 | 更新时可替换 |
| 用户数据目录 | 配置、数据库、账号凭据、用量记录、日志及后续 Agent 用户数据 | 更新时保留；数据结构变更需迁移 |

两个目录的具体路径、是否允许用户自选路径、卸载与数据清理方式尚未确定。安装状态和版本信息应与账号凭据区分，凭据保护方案待详细设计。

开发阶段正式版与 UAT 版使用同一源码、不同编译身份。正式版为 `xiaotao.exe`，默认数据目录 `%LOCALAPPDATA%\XiaoTao`，优先端口 `5455`；UAT 版为 `xiaotao-uat.exe`，默认数据目录 `%LOCALAPPDATA%\XiaoTao-uat`，优先端口 `5456`。两套环境的服务锁、窗口锁、窗口标题和桌面快捷方式也彼此独立，允许同时运行。UAT 首次启动时从正式版只读导入一次已登录的模型账号，并在 UAT 密钥环内重新加密保存；代理密钥、用量、配额、配置、Agent 会话、日志和运行时状态不共享。导入完成后两套账号独立维护，正式版文件不被 UAT 修改。会轮换 refresh token 的来源在两侧同时刷新时存在登录态互斥风险。该区分用于开发验收，不替代正式安装启动器与版本升级设计。

## 5. 服务接口与生命周期

建议使用以下路径划分，实际端口和接口协议待实现前确定：

| 路径 | 用途 |
| --- | --- |
| `/` | Web 管理页面，供桌面壳和浏览器访问 |
| `/api/...` | 页面使用的管理接口 |
| `/v1/...` | 供小涛 Agent 和外部工具调用的统一模型 API |

模型 API 以 OpenAI Chat Completions、Responses 和 Anthropic Messages 为兼容目标，按阶段实现并验证，不代表首版一次性完成所有协议。

关闭桌面窗口后应支持服务继续提供 API。建议使用托盘提供“打开小涛”“在浏览器打开”“退出小涛”等操作；默认关闭行为、退出时如何处理正在运行的请求及 Agent 任务尚待确定。

本地监听范围、管理接口与模型接口的鉴权、密钥存储、日志脱敏均需在实现前明确。默认使用场景是本机访问，局域网共享能力尚未确定。
