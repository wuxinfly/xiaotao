## 1. 产品定位与阶段范围

小涛客户端包含自研 Agent 和统一模型入口两部分。第一阶段先实现模型代理与管理，保留 Agent 的一级导航和架构位置，后续实现自研 Agent。

```text
小涛客户端
├─ 小涛 Agent
│  └─ 自研 Agent 的任务与交互界面（后续实现）
└─ 模型
   ├─ 仪表盘
   └─ 账号与配额
```

### 小涛 Agent

以现有 xt-skills 的能力和协作方式为基础，自行实现任务运行、模型调用、工具执行等流程，不依赖其他 AI 编码工具作为运行宿主。具体运行协议、工具权限和任务持久化机制待后续设计。

### 模型

支持反向代理渠道，以及用户自行配置的 API 地址、密钥和模型，通过统一入口管理、启停和调用。小涛 Agent 和外部工具均可通过统一模型 API 访问这些模型。

- 仪表盘：展示实时请求、用量、运行状态和错误等。
- 账号与配额：管理渠道、账号、API 配置、登录状态和可用额度；各来源提供模型目录入口，可按账号查看名称、复制完整模型 ID、刷新并区分实时与内置目录。
- 真实上游配额与本地统计用量分别展示；上游不支持配额查询时，不把本地估算显示为真实剩余额度。

## 2. 总体架构

采用“Go 本地服务 + Web 页面 + 轻量桌面壳”。服务承担核心能力，桌面壳和浏览器访问同一套页面、服务及用户数据。

```text
小涛分发 EXE
└─ 启动器：检查安装、比较版本、释放或更新程序
   ├─ Go 本地服务
   │  ├─ 托管 Web 页面
   │  ├─ 提供管理 API
   │  ├─ 提供统一模型 API
   │  ├─ 管理渠道、账号、配额、配置和用量
   │  └─ 后续启动和管理 Agent 进程
   └─ 轻量桌面壳
      └─ 打开本地服务提供的页面

普通浏览器 ──→ 同一套 Web 页面
外部工具   ──→ 统一模型 API
```

启动客户端时启动服务进程，默认通过桌面壳打开页面，同时支持通过普通浏览器打开。后续 Agent 可以作为独立进程，由本地服务管理。

### 技术决策及取舍

| 部分 | 已确认方向 | 理由与代价 |
| --- | --- | --- |
| 本地服务 | Go | 编译为独立 EXE，无需用户另装语言环境，适合 HTTP、SSE 和进程管理；需要移植 Python 渠道实现 |
| 用户界面 | Web 页面 | 桌面壳与浏览器共用界面；前端框架待定 |
| 桌面窗口 | 系统 WebView2 轻量壳 | 避免携带完整 Chromium；需处理机器缺少 WebView2 的情况，具体壳框架待定 |
| 分发 | 单 EXE 自动部署与启动 | 用户无需手动解压或经过传统安装向导；更新流程需处理运行中文件及失败恢复 |
| 数据存储 | 独立用户数据目录 | 程序更新不覆盖用户数据；数据库倾向 SQLite，驱动待定 |

不采用 Electron，优先控制分发包体。启动器可以使用 Go，尚未确定桌面壳是否同样使用 Go 或采用其他技术。前端静态资源可以嵌入 Go EXE，具体打包方式待定。最终包体需要以实际构建结果衡量。

建议在缺少 WebView2 时用默认浏览器打开页面，使服务和模型 API 仍可使用；运行时检测及回退策略尚待细化，不默认静默安装 WebView2。

## 3. 分发、安装与版本规则

对外分发一个 EXE，该文件携带对应版本的程序。首次双击自动部署并启动，后续双击根据已安装版本决定更新或直接启动。单文件分发不要求安装后的程序也只有一个文件。

| 状态 | 行为 |
| --- | --- |
| 尚未安装 | 释放程序到程序目录，创建桌面快捷方式，然后启动 |
| 已安装版本与启动器携带版本相同 | 直接启动已安装程序 |
| 启动器携带版本高于已安装版本 | 更新程序，保留用户数据，然后启动 |
| 启动器携带版本低于已安装版本 | 提示启动器过旧，继续启动已安装的新版本，不降级、不阻止使用 |

旧启动器提示应表达：“当前启动器是旧版，将启动已安装的最新版本，请检查是否使用了错误版本的启动器。”最终文案可在界面设计时调整。这里的最新版本指本机已安装版本，不代表已向远端查询最新发布。

桌面快捷方式用于日常启动，指向程序目录中的稳定启动入口；新的分发 EXE 用于首次部署或版本更新。版本比较规则、版本清单格式和稳定启动入口的具体实现待定。

### 绿色部署约定

- 不主动向 Windows 注册表写入小涛安装信息。
- 不登记卸载项、文件关联或注册表启动项。
- 通过程序目录和版本文件判断安装状态，不依赖注册表。
- 创建桌面快捷方式。

该约定不保证 Windows 或安全软件无法发现程序；操作系统自身的运行记录不属于应用可承诺消除的范围。

## 4. 程序与用户数据分离

| 目录 | 内容 | 更新原则 |
| --- | --- | --- |
| 程序目录 | 启动入口、服务 EXE、桌面壳、页面资源、视觉素材、版本文件及必要运行资源 | 更新时可替换 |
| 用户数据目录 | 配置、数据库、账号凭据、用量记录、日志及后续 Agent 用户数据 | 更新时保留；数据结构变更需迁移 |

两个目录的具体路径、是否允许用户自选路径、卸载与数据清理方式尚未确定。安装状态和版本信息应与账号凭据区分，凭据保护方案待详细设计。

开发阶段正式版与 UAT 版使用同一源码、不同编译身份。正式版为 `xiaotao.exe`，默认数据目录 `%LOCALAPPDATA%\XiaoTao`，优先端口 `5455`；UAT 版为 `xiaotao-uat.exe`，默认数据目录 `%LOCALAPPDATA%\XiaoTao-uat`，优先端口 `5456`。两套环境的服务锁、窗口锁、窗口标题和桌面快捷方式也彼此独立，允许同时运行。该区分用于开发验收，不替代正式安装启动器与版本升级设计。

## 5. 服务接口与生命周期

建议使用以下路径划分，实际端口和接口协议待实现前确定：

| 路径 | 用途 |
| --- | --- |
| `/` | Web 管理页面，供桌面壳和浏览器访问 |
| `/api/...` | 页面使用的管理接口 |
| `/v1/...` | 供小涛 Agent 和外部工具调用的统一模型 API |

模型 API 以 OpenAI Chat Completions、Responses 和 Anthropic Messages 为兼容目标，按阶段实现并验证，不代表首版一次性完成所有协议。

关闭桌面窗口后应支持服务继续提供 API。建议使用托盘提供“打开小涛”“在浏览器打开”“退出小涛”等操作；默认关闭行为、退出时如何处理正在运行的请求及 Agent 任务尚待确定。

本地监听范围、管理接口与模型接口的鉴权、密钥存储、日志脱敏均需在实现前明确。默认使用场景是本机访问，局域网共享能力尚未确定。

## 7. 第一阶段使用闭环

配置渠道或登录账号 → 获取模型 → 测试调用 → 开启统一代理入口 → 外部工具调用 → 仪表盘查看用量。

建议先实现自定义 API 接入，再选择最常用的反代渠道，验证流式输出、工具调用、取消请求、超时、凭据刷新和用量统计后逐步扩展。首批渠道及协议优先级尚未确定。

暂不把完整 Agent、全渠道接入、签到活动、复杂跨渠道调度纳入第一阶段。
